日期：2026-10-27（北京时间）。  
用途：记录已发生的过程，把经验封成下次可直接采用的开发方法。  
范围：记录 v0.1 流程沉淀及后续 v0.2 平台化。初轮仅整理方法，随后用户明确授权开发。以下旧阶段边界保留为过程，当前能力以 STATUS 和制作指南为准。

v0.2 已实现：标准包/库、SDK/沙箱、两套匿名 H5 模板、init/validate/pack 和集中 ZIP。内容制作流程为模板 → 修改 H5/讲稿 → 校验 → 打包 → 导入 → 配对演讲。第二套不同视觉与互动不修改内核；已验证无 baseline 启动匿名样例。

本轮经验：互动状态改为清单声明基础类型/范围，原课程规则移回其构建；模板的 data-step 选择器曾误选 body 导致回退空白，已限定在实际页面内并复测。完整包验证应覆盖解压启动与导入，不能只证明源码能跑。实际规范见 [制作指南](03-标准内容包制作指南.md)。后文“未实施”属于旧阶段记录。

## 3. 下次最快的复用方式

### 3.1 先确定是哪类工作

- **已有 H5 加手机遥控：**尽量保留现有视觉，建立明确的渲染适配接口。
- **新建 HTML 课件与手机系统：**先用匿名三页贯通，再增加实际内容与视觉。
- **复制已有工程形成新项目：**先抽出当前课件依赖，避免把旧资料与固定路径一起带过去。
- **原生 PPTX/PDF 或几百页课程迁移：**先比较原生适配、静态承载和 H5 重建，不能直接套小型 H5 的估算。
- **仅记录或研究：**停留在对应文档与假设层，不自动启动系统开发。

### 3.2 初始材料只收一次

确认目标平台、课件入口或源文件、逐页讲稿、图片/讲师资料、已有视觉、手机/浏览器、连接方式和预期交付。缺失项明确标注；已有材料不重复索要。

讲稿缺失要单独记录为内容补写，不能称为格式转换已经完成。照片、联系二维码和特定模型内容属于该次课件，不属于通用模板。

### 3.3 最小数据先贯通

用三页说明完整语义：第一页一步，第二页至少两步，第三页收尾；每页有独立 ID 和讲稿。

贯通目标：手机前进 → 本页展开 → 再前进换页 → 电脑回退 → 手机对齐 → 章节跳转 → 恢复状态。匿名样例可以减少第一次接入时把视觉问题和同步问题混在一起的概率。

### 3.4 再接内容与复杂视觉

复用同步、手机界面与配对。新课件补充内容和渲染适配。涉及旧代码构建变换时，检查变换是否命中，并遍历实际页面核对展开组数，不把一次成功的字符串替换当成通用转换器。

### 3.5 最后验证实际交付

根据变更跑相应自动化与浏览器操作，再做真实手机、真实网络和打包产物检查。交付时提供清楚的启动/停止入口、源码路径、运行说明、已通过项与缺口。

## 4. 什么能直接借鉴，什么仍需抽离

| 来源 | 复用价值 | 已识别的耦合 |
|---|---|---|
| `core/state.mjs` | 页序、步骤、黑屏、计时、状态转换 | 公开组件动作仍包含当前课件的特定 key 与范围 |
| `server/index.mjs` | 会话、配对、单主控、权限、SSE、命令检查 | 显式加载当前课件与三页样例，启动要求当前 32 页构建产物 |
| `clients/shared.mjs` | 客户端连接、发送限制、快照与前台恢复 | 与当前本机能力凭据和接口约定配套 |
| `clients/presenter/` | 手机讲稿、阅读控制与演讲工具 | 需要对齐目标内容结构和权限；不能带入旧配对状态 |
| `clients/display/generic.*` | 简单的内容演示起点 | 只支持有限的标题/条目结构 |
| `clients/display/adapter.mjs` | 给现有渲染器接同步 | 使用当前源课件全局变量与专用组件 |
| `packaging/build.mjs` | 公开/私有内容分离、资源和 HTML 输出 | 固定基线、素材路径、步骤映射与源码变换 |
| `packaging/launch.mjs` | 启停、日志、端口回退、实例识别 | 构建检查仍指向当前课件，需配置化 |
| `verification/` | 命令、权限与恢复案例 | 服务器案例断言当前 32 页和具体页面 ID |

因此当前工程是已验证的参考实现，还不是匿名、独立、无需适配的通用母版。

## 5. 封装分成三个层次

### 第一层：开发流程技能——本轮已做

本机技能位置：`C:\Users\deffc\.codex\skills\h5-phone-presenter`。

技能包含：

- `SKILL.md`：任务识别、最小闭环、同步约定与交付要求。
- `references/content-contract.md`：内容、讲稿、步骤与状态约定。
- `references/reuse-map.md`：来源工程位置、可复用文件与耦合清单。
- `references/verification.md`：实际遇到的问题和验证办法。
- `assets/minimal-deck/`：匿名三页清单与讲稿。

它的作用是帮助下一次 Codex 按已验证的经验开展工作，减少重新梳理和重复犯错。技能本身不提供可执行的完整演示引擎。

### 第二层：通用工程母版——待决定是否实施

候选结构继续采用 core、server、clients、adapters、decks、packaging、verification。将来源中的固定课件、资源、组件注册、默认入口和测试 fixture 抽为配置或内容。

只有满足以下条件才称为母版：

1. 没有当前用户的讲稿、姓名、照片、二维码、缓存或配对凭据。
2. 不依赖当前 `baseline/`，匿名三页课件能独立构建与启动。
3. 换第二套课件时，仅变内容与必要的渲染适配，不修改遥控内核和手机端。
4. 测试不再绑定固定页数和某位讲师的文字。
5. 复制后的新目录可完成配对、双向操作和退出。

项目初始化器属于该层的进一步自动化。当前未实现一条命令生成完整项目，也不因本手册自动进入开发。

### 第三层：用户面对的桌面产品——维持 H02 假设

课件库、编辑、AI 生成、统一桌面窗口、安装器、升级和数据管理，是产品体验层。它和开发流程复用分开评估，不能用“已封装技能”替代“软件已经完成产品化”。

## 6. 这次值得避免重走的问题

| 问题 | 本次处理或经验 |
|---|---|
| 只有交接 ZIP，容易忽略源码和私有资料 | 先看归档清单、构建来源与已有说明，保留基线 |
| 本机 Node 25.6.0 构建异常退出 | 附带 Node 24.22.1 验证通过；这是本机观察，不泛化成所有 Node 25 的缺陷 |
| 二维码选择了 VPN 虚拟网卡 | 标注虚拟网卡并提供 Wi-Fi 地址选择；实际互通仍要实测 |
| 同标签页打开新配对链接未重跑脚本 | 处理 `hashchange` 后重新配对，并清除已消费的链接片段 |
| 快照同步后再次发送翻页 | dispatch 和应用状态分开，统一服务端顺序 |
| 服务重启覆盖了电脑当前进度 | 已加载的电脑先单机接管，按 C 显式恢复当前画面 |
| 界面请求/切课件引起重复刷新或旧结果覆盖 | 处理重复导航和过期响应 |
| 测试错误等待关闭 dialog 可见 | 使用正确的 hidden/attached 状态，区分测试脚本问题和产品问题 |
| 截图抓到动画中间帧、移动视口实际未生效 | 等待/完成动画，读取真实 viewport 和 scrollWidth 核对 |
| 用浏览器移动视口代替手机结论 | 另外收集实际手机与网络反馈，准确记录 Edge 和系统浏览器 |
| 源码能跑却不知道 ZIP 是否完整 | 解压到另一中文路径，使用包内运行时启动并核验 |
| 文档仍写“从 M0 开始” | 用顶层文档和 STATUS 定义最新入口与阶段 |

Windows 启动、服务管理和测试不应影响用户正在使用的会话。需要重启、换课件等故障验证时，使用隔离实例。

## 7. 下次的检查清单

### 内容和同步

- 公开内容和私有讲稿分开，页面 ID 与稿件对应。
- 清单步骤数和真实渲染片段一致，分步与直接翻页有区别。
- 手机滚动和字号不改大屏，旧会话与重复操作不误执行。
- 原课件确认的内容、素材与互动按任务要求保留。

### 配对与恢复

- 二维码地址可选，凭据能过期与撤销；只允许约定的主控数量。
- 同标签页新配对、手机刷新、后台恢复和网络中断均有明确行为。
- 断线不积压翻页；电脑单机接管后有明确恢复入口。
- 无权限读取讲稿、任意文件或控制的请求被拒绝。

### 真机与交付

- 记录实际设备/浏览器/网络，不把模拟环境写成真机。
- 时间与容量结论来自真实经过时间和实际规模。
- 启动、重复启动、端口占用、停止、换目录解压均验证；干净机器另外记录。
- 包中没有旧会话凭据、临时日志或不属于新课件的个人资料。
- 使用说明明确项目在哪、启动哪个文件、故障怎样恢复和还有哪些未测项。

## 9. 如何知道复用确实提速

下次记录：材料齐备到三页闭环的时间、复用/修改了哪些模块、为了新课件改动核心的次数、首次真机配对是否成功、重复出现的问题、交付修复次数。

先观察第二套真实课件是否明显减少重复劳动，再判断是否投入工程母版或初始化器。不预先承诺固定生成时间或任意课件接入成本。
