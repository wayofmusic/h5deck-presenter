# 手机遥控与双屏演讲系统：开发计划

接手说明：先读 [00-顶层开发文档.md](00-顶层开发文档.md) 与 STATUS.md。本文的 M0–M6 是原始实施计划，当前基础已完成，不重复从 M0 开始；后续优先补稳定性与现有便携交付的验收。

版本：v1.0  
日期：2026-10-26（北京时间）  
状态：2026-10-27 v0.1 已通过 Redmi K70 Pro + Android Edge 基础真机验证；锁屏、另一网络与长时间验收待完成。以下为原始规划，最新完成情况见 STATUS.md。  

范围补充：2026-10-27 用户要求新增的内容生成、软件封装、眼镜提词与长课程方向先归档至 docs/HYPOTHESIS-POOL.md，本轮只做假设与边界研究，不将这些方向加入实施排期。
依据：顶层设计 v0.1  
首个课件：柴翔《如何用Y模型构建AI时代下的长期竞争力》，32页

## 1. 开发目标与方式

首版完成一个可实际演示的闭环：电脑一键启动，手机扫码配对，手机看当前页讲稿并控制分步翻页，电脑保持16:9纯投屏画面。

建议在Codex的独立本地项目中实施：项目文件、服务端代码、手机界面、测试记录和打包脚本放在同一目录，使用Git记录变更。当前对话继续承担需求和现场反馈也可以。

OpenAI官方快速开始将Codex定位为使用代码库上下文和开发工具的软件开发入口。[官方说明](https://learn.chatgpt.com/docs/quickstart)  
按里程碑保存规格、计划、验证和状态，有利于持续开发时保持上下文。[官方开发方法示例](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)

本功能首版不调用大模型API。先采用局域网，云端连接与原生PPTX适配另行安排。

## 2. 当前基础

已具备：

- 32页可离线运行的HTML演示，关键词、动画、背景和个人联系页已经完成。
- 按页分好的讲稿、提示、计划时长和章节。
- 前后翻页、分步展开、黑屏、计时、互动Y模型与本机画布保存。
- 可维护的源文件和本地构建脚本。

尚未具备：

- 手机与电脑之间的连接服务、配对与实时状态同步。
- 独立手机演讲者界面。
- 双屏模式的公开课件内容与私有讲稿分离。
- 断线恢复、控制凭据管理与便携启动交付。

开发必须保留现有演讲视觉和原有单机备用版本。开始前先保留基线，避免在正式使用的唯一文件上直接试验。

## 3. 三轮可用版本

| 版本 | 用户能实际使用什么 | 进入下一轮的条件 |
|---|---|---|
| v0.1 基础双屏 | 扫码连接、手机看稿、分步翻页、章节跳转、电脑键盘同步 | 当前32页同步闭环通过，至少完成一次实际手机连接 |
| v0.2 现场稳定 | 计时、黑屏、锁屏恢复、网络重连、重复点击防护、单机接管 | 故障场景和连续运行验证通过 |
| v1.0 复用交付 | 一键启动、第二套课件、完整说明、便携包、保留离线备用 | 更换课件不改遥控核心；干净Windows环境验证通过 |

这三轮按完成条件推进，不用未验证的工期替代验收。优先顺序是先连通、再同步、再完善阅读体验、最后验证稳定和打包。

## 4. 关键路径

M0 形成独立工程  
M1 验证实际手机能连接电脑  
M2 统一演示状态与当前课件接口  
M3 实现手机讲稿与控制界面  
M4 增加恢复与现场控制  
M5 验证课件复用  
M6 一键启动与交付演练

M1是真实网络风险检查。尚不能访问用户手机时，可继续M2的本地双客户端验证和M3界面开发，但不能把“模拟手机视口”写成“实机连接通过”。

## 5. 工作拆分

### M0：独立工程与基线

任务：

- 在交接包目录建立正式工程与Git版本记录。
- 明确core、server、clients、decks、adapters、packaging和verification的职责。
- 固定Node及依赖版本，生成依赖锁文件。
- 重建baseline课件，核对当前版本32页与主要画面。
- 记录基线构建方式、文件校验值和已有功能。

交付：可重新构建的当前课件、工程入口、运行说明、首个版本记录。  
完成条件：从现有源文件构建成功，不需要额外寻找聊天附件或临时目录图片；基线视觉不被改写。

### M1：先打通电脑与实际手机

任务：

- 启动仅服务所选项目的本地HTTP与实时连接服务。
- 选择可用网络地址，显示配对二维码和备用连接地址。
- 实现短时一次性配对凭据与一部主控手机。
- 用一个最小状态页面验证手机命令、电脑确认和状态回传。
- 检查会场网络或热点、网卡选择及系统浏览器兼容性。

交付：可扫码配对的连接原型与设备联调记录。  
完成条件：实际手机发出的动作有电脑确认；断开后可恢复；配对凭据失效后不能再控制。  
不得以手动关闭浏览器安全设置或防火墙作为默认交付办法。

### M2：统一状态与课件适配

任务：

- 为课件与页面分配稳定ID，拆出公开清单、讲稿和讲师资料。
- 统一next、prev、go、渐进步骤、黑屏、计时和公开组件状态。
- 本地服务维护有序会话状态，命令带ID去重。
- 实现状态快照应用，防止收到同步事件后再次发送同一操作。
- 接入当前32页，保持桌面键盘、手机命令相同语义。
- Y模型数据按课件命名空间保存，避免迁移造成覆盖。

交付：演示核心、当前课件适配器、内容格式校验、同步接口。  
完成条件：电脑与第二客户端交替操作，页面ID、步骤和讲稿始终一致；直接翻页与分步前进可明确区分。

### M3：手机讲稿与遥控界面

任务：

- 手机显示当前页标题、页码、逐页讲稿、现场提示及下一页标题。
- 常用控制置于单手易点位置，提供章节跳转和直接翻页入口。
- 字号调整、手动滚动与阅读位置记录只影响手机。
- 增加可关闭自动滚动：手动滚动暂停，不自动触发翻页。
- 正式投屏不显示讲稿、配对码、网络提示或调试信息。
- 沿用黑白红视觉，优先保证讲稿阅读和按钮辨识。

交付：手机演讲者页、电脑投屏页、电脑设置页。  
完成条件：文字无横向溢出；手机操作不改变电脑16:9排版；电脑翻页后手机显示正确讲稿；控制按钮真实响应。

### M4：现场稳定与异常恢复

任务：

- 统一总计时和练习计时，恢复连接后校正。
- 手机后台恢复时先读完整状态，再开放控制。
- 断线不缓存翻页；重复、过期和旧会话命令不执行。
- 电脑可撤销主控并重新配对。
- 服务异常时电脑进入明确的单机接管；重新接管遥控时，以当前电脑画面重新建立状态。
- 常亮和全屏按浏览器能力增强，不作为基本功能成功前提。

交付：恢复策略、故障提示、验证记录。  
完成条件：锁屏、断网、刷新和服务重启不会让画面误跳；恢复后计时与页码正确。

### M5：验证未来复用

任务：

- 制作另一套三页测试课件，使用不同标题、讲师、图片、讲稿与主题。
- 第二套课件至少包含一页两步展开，验证控制不是写死32页。
- 新增内容包时不修改手机遥控和连接服务。
- 内容检查覆盖重复页面ID、漏配讲稿、资源缺失与版本不匹配。
- 将Y模型作为当前课件组件，而不是所有演讲都必须加载的功能。

交付：第二课件、内容格式说明、替换教程。  
完成条件：同一启动器切换两套课件，讲稿、逐步动画、计时和阅读位置不串场。

### M6：一键启动与正式交付

任务：

- Windows启动入口完成运行环境检查、端口选择和网络地址提示。
- 优先交付附运行环境或打包后的版本，正常使用不要求手工执行开发命令。
- 保留当前可双击的离线HTML作为单机备用。
- 将课件、素材、必要运行环境和说明整理为自包含交付包。
- 进行一次完整连接、投屏、遥控、暂停、恢复和结束流程的演练。
- 连续运行60分钟，记录计时、页码与连接异常；不能只修改计时变量来代替运行验证。

交付：启动器、正式包、使用说明、验收记录、已知限制。  
完成条件：干净Windows环境按说明可启动；实际手机联调完成；未覆盖的手机与网络环境明确列出。

| 验证 | 通过标准 | 证据 |

## 7. 实施规则

- 每完成一个里程碑，先验证并修复，再记录状态。
- 把任务状态、运行办法、决定和未解决问题写回STATUS.md。
- 需求或接口发生变化时，先更新设计与计划，避免接口各自漂移。
- 不更改柴翔已经确认的主屏文案、肖像和微信二维码，不重新生成二维码。
- 不将桌面端的“备注隐藏”当成公开内容与私有讲稿已真正分离。
- 不自动开启公网、不上传讲稿与个人资料、不修改无关项目。
- 首版不扩展账户、付费、语音跟稿和原生PPTX遥控。

## 8. 开发前需要补充的实际信息

| 信息 | 对开发的影响 | 未获得时可继续什么 |
|---|---|---|
| 手机型号与系统 | 决定首个实机浏览器 | 本地协议、桌面接入、手机界面 |
| 常用投屏与网络方式 | 决定M1联调路径 | 内容格式与状态核心 |
| 讲稿使用版本 | 决定script.json的内容 | 同步结构可先用现有逐页备注 |
| 手持或放讲台 | 决定按钮和滚动习惯 | 先提供单手可操作的默认布局 |

这些信息不必全部齐备才能开始；真实手机不可访问时，明确保留实机验收缺口。

## 11. 2026-10-27 执行反馈

交接已核对，32 页基线可重复构建，正式工程已进入可运行 v0.1。按用户回复，首轮实机目标为 Android Chrome，网络优先同 Wi-Fi 与手机热点。实现与证据详见 STATUS.md；M1 和 M6 的真机/环境验收仍须完成。

下一步顺序：实际 Android 扫码与交替控制 → 同 Wi-Fi/手机热点分别验证 → 锁屏一分钟、后台与网络恢复 → 30 分钟共享计时、60 分钟连续运行 → 干净 Windows 解压运行。按真实结果完善交付包，不以同机浏览器替代实机验收。

首轮实机结果已收到：Redmi K70 Pro 使用 Android Edge，用户确认逐字稿对应、手机控制 PPT、电脑翻页后手机跟随三项正常。Android Chrome 尚未使用；后续从锁屏、另一网络和 Chrome 补测继续，不重做已确认的基础闭环。

追加实机结果：小米 Mi 10 Pro 使用系统自带浏览器，在与电脑同一 Wi-Fi 下也使用成功。同 Wi-Fi 场景已确认，后续网络测试聚焦手机热点，不将此次反馈扩展到锁屏或长时间稳定性。

scrcpy 官方文档调研见 docs/SCRCPY-RESEARCH.md，作为可选 Android 观察和录屏工具，不作为同步依赖。
