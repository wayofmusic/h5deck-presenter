# 固定演示平台 + 可替换内容包｜标准草案

日期：2026-10-27。状态：历史架构草案。后续用户授权后，v0.2 已实现标准包/库、SDK、模板和制作工具。

> 本文保留讨论时的假设、字段和验收设想，不是当前接口规范。实际实现请读 [03-标准内容包制作指南](03-标准内容包制作指南.md)。下文“当前 v0.1 / 未开发”均指草案形成时；未在制作指南与 Schema 中定义的能力，不视为已支持。

用户提出的方向：平台功能固定，每套课件填入不同的互动 HTML 和对应演示备注，框架复用、内容可替换；同时标准化符合平台要求的内容生成。

本文将该方向写成可审查的规范。拟议的 `.h5deck`、内容导入、桥接协议、SDK、校验器和课件库均未在当前 v0.1 实现。当前可运行版本仍按 STATUS.md 的实际能力使用。

## 1. 产品分成两个交付单元

| 单元 | 内容 | 用户怎样使用 |
|---|---|---|
| 平台程序 | 配对、连接、手机看稿、统一控制、计时、恢复、内容管理 | 同一平台持续使用，不因换课重复复制运行时和服务器 |
| 每套课件的内容包 | 互动 H5、素材、页面清单、讲稿、提示、必要适配 | 一门课一个包，导入后由平台检查并加载 |

拟议内容文件扩展名为 `.h5deck`，本质为有规范目录和清单的 ZIP。扩展名不等于格式能力已实现，也不构成不可调整的最终命名。

平台内部仍可分模块，使用者面对统一入口。程序交付文件与每门课的内容文件分开，可以减少换课时复制整套应用的成本。

## 2. 功能归属

| 平台固定能力 | 内容包负责 | 可通过平台配置的内容 |
|---|---|---|
| 服务启停、会话、配对与撤销 | 页面文案、版式、动画与素材 | 默认课件、主题与讲师公开资料 |
| 命令检查、状态顺序与恢复 | 页面顺序、标题和展开组数 | 默认字号与阅读偏好 |
| 手机讲稿界面、目录和常用按钮 | 逐页备注、段落、提示和建议时长 | 是否启用包声明且平台支持的能力 |
| 总计时、黑屏和窗口管理 | 内容专用互动与状态说明 | 播放清单等未来扩展 |
| 内容包检查、资源访问与版本匹配 | 与平台协议连接的适配逻辑 | 明确支持的配置项，不是任意服务端脚本 |

新的互动通常写在内容包的 HTML/JS 内。若互动需要新服务器能力、多人同时参与或系统权限，需另外评估，不能归为“换内容就自动拥有”。

## 3. HTML 兼容范围

| 内容类别 | 目标接入方式 | 边界 |
|---|---|---|
| 平台模板生成的内容 | 自动满足内容与桥接约定 | 优先研究的标准生产路径 |
| 按协议制作的自定义互动 HTML | 通过其适配器报告页面信息、接收状态和提交操作意图 | 可以有自己的视觉与互动，不需复制整套平台 |
| 已有、未适配的 HTML | 先检查其导航/展开机制，再写适配层 | 仅能打开网页不代表能遥控、正确换稿或恢复步骤 |
| 原生 PPTX、PDF、视频或远端网站 | 单独研究转换或渲染适配 | 不能由 H5 内容标准直接推导无损支持 |

接入基于协议和内容格式，避免平台为每套课硬编码页面文案或 DOM 选择器。既有网页内部导航、动画和互动需要映射成统一语义。

## 4. 目标内容包结构

```text
某门课程.h5deck
  manifest.json              包身份、版本、入口、能力与页面清单
  presentation/
    index.html               演示入口
    style.css                课件样式
    content.js               课件内容或交互逻辑
    adapter.js               本包到平台协议的适配
  assets/                    本地图片、字体、音视频等
  private/
    notes.json               逐页讲稿与提示
```

这是结构草案，不要求所有课件一定拆成相同数量的脚本；单文件 H5 也可作为入口，但仍需清单、讲稿和明确的适配能力。

`private/` 命名不自动提供保密。导入服务必须分别处理可公开资源和私有讲稿，私有文件不能由一般静态文件路由读取。内容包包含讲师资料，分享整个包也会分享包内文件；观众版导出需另行定义去稿规则。

## 5. 清单草案

下面仅表示建议的字段与含义，尚未冻结为平台实现或已发布 JSON Schema：

```json
{
  "packageFormat": "h5-presenter-content/1-draft",
  "schemaVersion": 1,
  "deckId": "example-course",
  "revision": "1",
  "title": "示例课程",
  "entry": "presentation/index.html",
  "adapter": {
    "protocol": "h5-presenter-bridge/1-draft",
    "path": "presentation/adapter.js"
  },
  "notes": "private/notes.json",
  "capabilities": {
    "navigation": true,
    "reveal": true,
    "widgetSnapshot": false
  },
  "slides": [
    { "id": "opening", "title": "开场", "steps": 1, "seconds": 30 },
    { "id": "two-points", "title": "两个重点", "steps": 2, "seconds": 60 },
    { "id": "closing", "title": "收尾", "steps": 1, "seconds": 30 }
  ]
}
```

约定：

- `deckId` 标识课程，`revision` 标识本次内容修订，包版本、桥接协议与软件版本分别管理。
- 页面 ID 与页序分开；重排页序保留对应页面身份，替换内容时由编辑规则决定是否沿用身份。
- `steps` 表示可见状态数量。若与当前内核保持一致，进入页面为步骤 1；例中第二页再前进一步显示步骤 2，再下一步进入第三页。
- 声明的能力必须实际可用；没有分步展开就用一步，不伪造动画能力。未支持的能力不能由平台静默当成成功。
- 适配器由内容入口按约定加载，平台通过消息协议交互，不在服务端执行包内任意脚本。
- 资源使用包内相对路径；网络依赖需要声明，离线可用性另外验证。

## 6. 备注格式草案

```json
{
  "deckId": "example-course",
  "revision": "1",
  "slides": {
    "opening": {
      "cue": "站定以后再开始。",
      "paragraphs": [
        { "id": "opening-p1", "text": "这部分是讲师的逐字稿。" }
      ]
    },
    "two-points": {
      "cue": "讲完第一点后，再展开第二点。",
      "paragraphs": [
        { "id": "two-points-p1", "text": "先讲第一个重点。" },
        { "id": "two-points-p2", "text": "展开以后，再讲第二个重点。" }
      ]
    },
    "closing": {
      "cue": "停顿，结束本段。",
      "paragraphs": [
        { "id": "closing-p1", "text": "用一句话收束本段内容。" }
      ]
    }
  }
}
```

每个公开页面应有对应备注或明确的无稿声明。备注与清单必须是同一课件、同一修订；错误匹配应在导入阶段发现，不在演讲过程中默默显示错稿。

“下一段文字”与“下一张幻灯片”分开控制。即使以后接入眼镜或语音跟稿，也不以备注滚动位置自动决定投屏翻页。

## 7. 平台与 H5 的适配约定

### 7.1 统一控制流程

**手机或 H5 提出操作意图 → 平台校验并产生新状态 → 平台广播快照 → 内容渲染与手机讲稿更新。**

H5 内自带导航按钮也应走这条路径。避免它独立换页后再与平台争夺当前状态。应用快照不再次提交同一操作。

### 7.2 候选桥接接口

| 接口/消息 | 作用 |
|---|---|
| `CONTENT_READY` | 内容加载后报告协议、课程/修订、能力和就绪情况 |
| `APPLY_SNAPSHOT` | 平台要求内容展示指定页面、步骤和公开互动状态 |
| `SNAPSHOT_APPLIED` | 内容确认已应用对应状态版本，便于识别渲染失败 |
| `CONTENT_INTENT` | 页面内按钮/键盘/互动提交统一命令意图 |
| `CONTENT_ERROR` | 明确报告入口、资源、协议或渲染异常 |
| `DESTROY` | 结束该内容实例的监听、计时器与占用资源 |

以上为候选名称，不是当前已经可调用的 SDK。落地时需冻结消息结构、握手、超时、错误码与协议版本兼容规则。

### 7.3 互动状态

- 本地临时状态，如悬停和编辑中的文字，可留在内容内部。
- 对观众展示且需要刷新恢复的状态，如选项、标签页和图表筛选，应可序列化，并通过平台统一版本管理。
- 动作名称、参数与状态范围需要声明和校验。平台不能为了支持任意互动而直接执行内容包中的服务端代码。
- 包未声明互动恢复能力时，不能宣传它的所有复杂互动都可在断线后自动还原。

### 7.4 内容与平台隔离

可研究 iframe 与消息桥，使内容样式和脚本不会直接覆盖平台界面。窗口通信需要检查发送来源、目标内容实例、协议和消息结构，不能只收到任意消息就执行命令。私有稿件权限和本机管理凭据不交给公共内容页面。

实施前需选择并验证隔离方式，例如受限 iframe、独立内容来源或专门的消息通道；sandbox 导致的来源差异也需处理，不能简单拼接属性宣称已经隔离。

当前 v0.1 的页面路由默认发送 `X-Frame-Options: DENY`，没有按内容嵌入设计。未来若采用 iframe，需专门调整内容路由与隔离策略，同时继续保护管理页；当前没有改动这些路由。

参考：[MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)、[MDN postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage)。这里是架构推断与设计要求，不是当前功能验收。

## 8. 如何标准化生成内容

### 8.1 两个入口，同一输出标准

1. 软件内 AI 或人工输入：主题、听众、目标、时长、资料、风格与互动需求。
2. 外部 AI 内容导入：按指定的结构化内容约定产出，再由相同流水线检查与渲染。

候选流水线：

**资料 → 大纲 → 逐页内容/讲稿 → 结构校验 → 模板生成 H5 → 桥接检查 → 视觉/交互检查 → 打内容包。**

模板生产常规页面，自定义 HTML 制作特殊互动；两者最终遵守同一个平台协议。这样可以逐步减少每次重新实现导航、配对与手机界面的工作量。

### 8.2 给内容生成工具的约束

- 页面有唯一且可持续关联的 ID，画面文案与讲稿分开。
- 屏幕优先呈现要点，解释放在备注；文字密度依据用户选择的风格。
- 每页明确展开组数、建议时长和下一页顺序。
- 事实、数据与案例来自输入材料；缺依据时标记待补，不补造结果。
- 资源明确来源、位置与依赖；图片未提供时不要引用不存在的本地文件。
- 标准互动采用已支持的组件；自定义互动另行声明状态与控制方式。
- 输出后经模板和桥接检查，不把“生成了一份 HTML”当成平台接入已经完成。

### 8.3 可复用的生成指令草案

```text
为演讲平台制作一套标准内容包，先输出大纲与逐页结构供编辑。
画面内容与逐字稿分开，每页使用唯一 ID，列明标题、公开内容、展开组数、建议时长、备注段落和现场提示。
只使用当前模板库明确支持的页面与互动类型。需要自定义 HTML 时说明适配和状态要求。
保留材料中的事实边界，不编造数据、经历或不存在的素材。
经内容结构、资源、页面步骤、讲稿对应与平台桥接检查后，再生成交付包。
平台和内容协议以本次采用的已发布版本为准；草案或未实现能力不得当作可用接口。
```

这里定义的是生产流程，模板库、Schema、SDK、自动校验与 AI 接入仍需在选入开发后具体实现。

## 9. 导入与交付的检查目标

候选检查器分四层：

1. **包与资源：**清单可解析、入口存在、路径在包内、资源存在、版本受支持，解包时防止越界写入。
2. **内容对应：**页面和段落 ID 合法、讲稿对应、步骤为正数、能力声明一致。
3. **运行协议：**能就绪、接受指定页/步骤、回报已应用版本，页面内操作通过平台处理。
4. **体验质量：**16:9/约定布局、无裁切、无相关脚本错误、媒体能加载、手机稿件正确、断线与刷新行为符合声明。

自动结构校验不能代替视觉与实际互动检查；打包成功也不表示课程内容已经讲得好。

平台兼容性与内容质量分别给出结果，例如“协议检查通过，但某页文字过密”；不能用单个成功标记掩盖不同问题。

## 10. 迁移当前工程的候选顺序

以下仅是未来被明确选入开发后的建议：

1. 用匿名三页内容定义协议和 fixture，冻结第一版可验证约定。
2. 把当前显式注册两套课件的逻辑改为受校验的内容管理入口，移除默认启动对 32 页基线的强依赖。
3. 抽离平台通用状态与课件专用互动动作，完成内容实例生命周期。
4. 当前 32 页用适配器接入，保留原有文案和视觉；手机端继续复用。
5. 用第二套明显不同的互动 H5 验证可替换性，换内容时不改平台连接、遥控内核和手机端。
6. 再研究内容生产模板、生成工具、统一桌面封装和更大课程规模。

当前工程的耦合清单见 [复盘与复用手册](01-开发复盘与复用手册.md)。

## 11. 完成平台化的判断标准

只有以下场景真实通过，才称为“固定平台 + 可替换内容包”已经实现：

- 同一套平台程序导入至少两套独立内容包。
- 第二套内容的文字、布局和互动与第一套不同，但不改平台核心/连接/手机端代码。
- 两套内容均可配对、换稿、分步、跳转和按声明恢复状态。
- 删除、升级或替换内容包，不覆盖其他课程和私有稿件。
- 不合规范的包明确报错，未适配 HTML 不冒充支持完整遥控。
- 用户只需选择或导入内容包，不手工编辑服务端的课件数组或素材路径。

当前三页样例只证明内核可以接不同数据，不足以满足这套完整平台化验收。

整体开发范围见 [顶层开发文档](00-顶层开发文档.md)，当前事实见 [STATUS.md](STATUS.md)，本方向继续留在假设池，等待后续明确的实施范围。
