# 产品假设池与能力边界

记录日期：2026-10-27（北京时间）。

状态：保留研究、成本与边界。后续用户已授权 H07/H08 的标准内容平台部分，v0.2 已实现包/库、SDK、模板与 CLI。AI、安装器、眼镜、长课程与原生 PPT 继续只作假设。下文 H07/H08 的“拟议/未实现”为初始研究记录，当前能力见 [STATUS](../STATUS.md) 与 [制作指南](../03-标准内容包制作指南.md)。

整体范围与假设转入开发的规则见 [顶层开发文档](../00-顶层开发文档.md)。本文记录设想与研究材料，不作为直接实施任务。

用户明确要求：后续提出的内容生成、软件封装、AI 眼镜、几百页多天课程等方向，先放入假设池，不因提出想法而安排实现。本文中的路线、优先级、验证步骤均为研究建议，不是已经支持的功能、开发排期或性能承诺。

## 1. 已知事实与用户意向

### 已有实测事实

- v0.1 已接入当前 32 页 H5 演讲与独立三页复用样例。
- Redmi K70 Pro + Android Edge：用户确认逐字稿对应、手机控制 PPT、电脑翻页后手机跟随均正常。
- 小米 Mi 10 Pro + 系统自带浏览器：用户反馈同一 Wi-Fi 下也使用成功。
- 同机浏览器验证过 100 次命令、20 次两端交替、10 秒断线恢复、撤销配对、服务重启后电脑显式恢复；详细边界见 STATUS.md。
- 当前是目录式便携工程，含启动/停止脚本与 Node 运行时，还没有统一安装器、桌面内容编辑器或自动课件生成器。

### 已表达的方向偏好

- 用户希望软件内 AI 生成与外部 AI 内容导入两种方式都能支持。
- 先做自己使用的工具，再推广，根据实际需求决定是否产品化。
- 用户提出眼镜提词方向，希望减少背稿与低头看手机的负担，专注表达与表演。
- 用户关心几百页、多天课程的迁移成本和系统上限。

以上是意向与问题记录。其中 H07/H08 的标准内容平台部分已进入 v0.2，其余仍为假设。

## 3. 内容生成系统：可能形态

候选工作流：资料输入 → 大纲确认 → 逐页内容与逐字稿 → 模板渲染 → 页面编辑 → 排练 → 手机互联演讲。

两种入口最终进入同一个可编辑内容包：

1. 软件内 AI：输入主题、听众、目标、时长、素材与讲师资料，逐步生成内容。
2. 外部 AI 导入：先支持明确的 Markdown/结构化文本约定，导入后预览和修正。Word、PDF、既有 PPT 是各自独立的解析与迁移问题，不能混称已经支持。

候选实现原则：让 AI 产出受约束的页面内容和讲稿，由模板负责排版。这样有机会延续现有黑白红、大字、渐进展开的风格，并维持页面与讲稿对应关系。自由生成任意 HTML 的版式、脚本和同步接口稳定性需要另行验证。

每页至少区分：页面标识、公开画面、讲稿段落、现场提示、建议时长、展开步骤、资源引用。改一页、换页序或重生成某段时，讲稿和资源需能继续对应。跨版本页面标识的迁移策略尚未设计。

AI 生成后的人工作业同样要计入成本：事实核验、口语修改、节奏、素材与版权确认、排版检查、排练。现有资料没有讲稿时，新增讲稿属于内容研发，不属于单纯格式转换。

## 4. “好的封装”的具体含义

封装假设同时涉及程序交付和使用流程：

- 一个应用名称、图标与启动入口。
- 应用内管理课件、编辑、预览、配对、演讲与导出。
- 应用统一管理本地服务的启动、状态、退出和重复启动。
- 安装文件、用户内容、配置、日志分别有明确位置；界面提供打开数据目录与备份入口。
- 软件升级保留用户课件，课件可导入/导出，不依赖手动改代码目录。
- 演讲时电脑与手机保持现有独立画面。

技术候选：Electron 可复用当前 Node 与网页实现，官方打包流程可生成桌面发行物；Tauri 使用系统 WebView，若保留 Node 服务还需设计后端或 sidecar。选择尚未定案，不承诺安装包大小和无提示安装体验。

“用户只面对一个入口”不等于磁盘上只有一个文件。应用本身仍需要资源与数据。独立 HTML 可以作为离线放映导出格式；手机互联仍需要正在运行、可互通的连接服务。

## 5. 几百页课件：先选转换目标

页数不是唯一成本因素。需要先辨别：已有讲稿是否齐全、需要保留的动画/视频/图表、是否要求可编辑、是否重新设计视觉、原始软件和字体条件。

| 路线 | 可能保留的能力 | 主要取舍 | 相对成本来源 |
|---|---|---|---|
| 保留原生 PPT，另接手机看稿 | 由原软件运行页面、动画与媒体 | 需要指定软件适配；当前 H5 服务不直接控制原生 PPT | 适配与备注/步骤映射，避免全量视觉重建 |
| 导出静态页面，再放入 H5 阅读/遥控容器 | 页面静态外观与逐页讲稿 | 页面变为静态；原生动画、视频、对象编辑需另处理；字体和导出结果仍须核验 | 批量导出、讲稿对应与逐页质检 |
| 重建为可编辑原生 H5 | 统一模板、网页互动和定制动画 | 复杂图表、公式、SmartArt、视频、动画等需要映射或重做 | 模板开发、异常页修复、逐页重建与回归 |
| 混合方式 | 普通讲义保留静态展示，重点页做原生 H5 | 需要统一页序、内容标识和讲稿关系 | 将高成本改造集中于少量关键页 |

“几百页已有课件全部重做成当前 32 页演讲式视觉”与“原样带入课件并能看稿遥控”是两项不同工作。前者涉及课程内容与视觉重构。

对成熟长课程，低成本路线的研究方向是：尽量保留现有课件的可用价值，先验证静态承载或原生适配，关键页再判断是否值得重建；不要预设所有页面都要重新生成。

### 成本估算框架

总成本 = 导入准备 + 普通页数量 × 核验时间 + 异常页数量 × 修复时间 + 互动页数量 × 重建时间 + 缺失讲稿的补写/审稿 + 媒体处理 + 整课验收。

仅作算术示例：假设 500 页每页人工核验 1 分钟，核验本身就需要 500 分钟，即 8 小时 20 分钟；这不是实测单页耗时，也未包含重建和补稿。必须用真实课件样本估计各类页面占比，不能给出统一每页价格或承诺一键无损。

今后若验证，应从一套完整课程中抽取覆盖各种页面类型的样本，包括普通文字、图表/公式、图片、媒体、动画、互动、隐藏页与备注缺失页；只测若干简单页不足以估计几百页成本。

## 6. 当前边界与潜在上限

| 维度 | 当前事实 | 未来研究方向与未知 |
|---|---|---|
| 页数 | 实测 32 页主课件与三页样例；代码未写统一 32 页上限 | 没有 300/500/1000 页容量实测，不能声明这些规模已支持 |
| 渲染 | 当前只渲染活动页面；手机读取整套讲稿和目录 | 大课件可研究按章节读取讲稿、目录检索与资源预加载；当前并非已经实现 |
| 文件体积 | 当前单文件离线课件约 16.3 MB | 几百张图片/视频可能成为主要负担；ZIP 大小、传输量与浏览器内存不是同一指标 |
| 课件输入 | 当前课件适配与结构化三页样例 | 任意 PPTX/PDF/网页自动导入、无损转换均未实现 |
| 内容制作 | 当前课件已有逐字稿 | AI 自动生成与编辑系统尚未实现；输入资料质量与人工审核决定内容上限 |
| 课程时长 | 已有演讲计时与练习计时 | 30/60 分钟连续验收未完成，多日课程不能据此宣称稳定 |
| 跨天继续 | 当前服务端会话主要在内存，电脑窗口保留时可显式恢复 | 服务与所有窗口关闭后，多天断点续讲、已讲/跳过标记、版本迁移尚未实现 |
| 同时控制 | 当前仅一部主控手机 | 多讲师、多主控、分组课程和多会话未验证或未实现 |
| 网络 | 同一 Wi-Fi 已有用户成功反馈 | 手机热点独立验收、公网跨网络与离线缓存策略仍未完成或未实现 |
| 眼镜 | 没有眼镜设备接入或实测 | 设备显示能力、官方接口、网络和输入方式均需针对型号验证 |
| 用户范围 | 个人使用，已有两部手机反馈 | 安装维护、他人课程差异、推广需求与商业模式尚未验证 |

页数增加本身不要求同步所有页面：演示状态可以继续只携带当前页面与步骤。潜在瓶颈更多来自资源、目录、讲稿加载和恢复策略。这是基于代码结构的推断，不是几百页已通过的性能结论。

### 将来才进行的容量验证

100、300、500、1000 页可作为分级测试样本，而不是支持声明。届时记录：冷启动、首屏、任意页跳转、手机讲稿获取、翻页延迟、内存、媒体载入、后台恢复、跨天断点与版本变化。

多天课程的潜在模型是“课程 → 天/章节 → 课时 → 页面”，一次授课记录与课件内容分离。备份、关机后继续和重复授课，比让进程连续运行数天更值得先验证。

## 7. AI 眼镜假设 H04

### 可探索的体验

电脑对观众展示 PPT，讲师在手机或眼镜上看私人提示。眼镜优先尝试关键词、当前一句/下一句、停顿提示和页码，显示多少文字应由实际阅读测试决定。

提词跟随与 PPT 翻页应是不同状态：读到哪里，不应天然等于大屏自动翻页。手机、脚踏或眼镜输入可作为控制候选；语音跟稿属于额外衍生假设，不作为现有能力。

### 官方接口调研结论

- Android XR 文档说明，可以由手机应用中的 projected Activity 向兼容音频/显示眼镜提供体验，并在运行时检查视觉界面能力。该路线意味着可能需要 Android 伴随应用，不能承诺现有 H5 地址直接通用。
- Meta 官方文档说明，Meta Ray-Ban Display 有基于 HTML/CSS/JavaScript 的 Web Apps 路线，并提供 fetch/WebSocket 等连接能力。它说明网页提词存在可研究的实现路径；具体区域、设备设置、本机局域网接入、显示效果和长时间佩戴仍未验证。
- “AI 眼镜”并不保证有显示屏，需按具体设备确认。上述资料不是购买建议，也不是所有眼镜兼容性结论。

### 要验证的核心问题

同一段真实讲述，对比手机提词与指定眼镜提词，观察准备时间、低头次数、卡顿、漏句、眼神自然度、观众感受、可读性和疲劳。若减少低头却明显增加阅读僵硬或疲劳，假设需要调整。

先区分三项假设：内容生成可否减少备稿成本；提词可否减少背稿负担；眼镜可否让提词更自然。不能用“支持眼镜”直接推导“无需准备和排练”。

## 10. 2026-10-29 后续候选路线（仅规划，未授权实施）

用户询问“后续还能做哪些开发”。依据 v0.2 的现状，建议先补齐新版真实设备验收，再逐步补内容制作闭环。下列顺序是讨论建议，不是版本排期；本次未改应用功能，也未更新交付 ZIP。

| 顺序 | 候选方向 | 用户能得到什么 | 最小验证与边界 |
|---|---|---|---|
| 0 | v0.2 稳定性与连接诊断 | 用新版课件包现场演讲更可判断、故障有明确提示 | 两套标准包分别实测手机扫码、逐页稿、展开与后台恢复；再补热点、真实时长、干净 Windows。只读诊断不自动改变防火墙设置 |
| 1 | 轻量内容工作台（细化 H02/H08） | 课程卡片/预览、逐页改稿、课程备份/导出、版本与资源管理，减少手改文件 | 先用一门真实课程完成导入→改某页稿→保存新修订→手机核对→备份恢复；保持页 ID，升级不丢 data。任意自定义 H5 的自由画布编辑不自动包含 |
| 2 | 模板式内容制作与外部 AI 结果导入（细化 H01/H08） | 选模板，填写/导入大纲、逐页要点和讲稿，界面预览并生成 .h5deck | 先支持明确结构的文本/JSON，生成受控页面类型；模板内容支持编辑，自定义 H5 继续走适配。Word/PDF/PPTX 解析另行立项 |
| 3 | 软件内 AI 辅助制作（H01） | 资料→大纲确认→逐页画面/稿→预览修改；支持只改一页 | 与外部制作共用同一内容标准；保留事实核验、费用/重试边界和版本回退，不承诺一次生成即可直接授课 |
| 4 | 成品应用封装（H02） | 统一窗口/退出、数据入口、安装升级并保留课程 | 工作流稳定后验证安装→制课/导入→配对→演讲→升级→数据保留；安装器不代替稳定性验收 |
| 后续 | 章节化长课、跨天进度、旧 PPT 迁移、眼镜（H04/H05/H06） | 支持更大课程和新显示设备 | 按真实课程/指定软件与硬件先做样本；不纳入上一轮平台化已完成的能力 |

最建议的下一项新功能是“轻量内容工作台”：先让使用者在界面内改讲稿、预览和管理内容；随后模板生成、外部 AI 和软件内 AI 可以共用它。模板与 AI 的目标是降低每次制课的制作/修改成本，不能仅以生成速度评估。

候选完成标准：给一份真实资料，使用者能从界面得到可导入演示包，并能改一页内容或稿件而不破坏页面对应和已有课程。不据此提前声明任意资料格式、任意 H5 或几百页性能支持。

### 2026-10-29 补充：从录音/逐字稿重建课程（H01 候选输入）

用户询问如何用逐字稿复刻课程，也可能持有其他讲师的授课录音。本轮仅解释方法，未新增音频上传/转写或自动制课功能。

候选流程：音频保留时间码与讲师/学员区分 → 校对专有名词/数据并标记听不清 → 建素材与来源索引 → 提取目标学员、学习结果、课纲、方法/案例/练习 → 确认忠实还原还是面向自身授课重构 → 拆成逐页画面要点与独立讲稿 → 制作标准内容包 → 双端排练验收。

录音只支撑听得到的内容，不能据此声称恢复了原 PPT 版式、图表和现场动作。新增图示、练习与推断的分页须标明为设计建议；原始逐字稿与加工稿分别保留。其他讲师的经历/案例不能改称用户本人经历，借鉴保留来源，需要原样复用的内容先明确可使用范围。

后续可用一段 10–20 分钟的代表性材料先验证转写准确度、页稿对应、人工修改量与实际可讲性，再估计整课成本；长录音分段维护统一索引，未完整处理不声称全量还原。当前平台只负责承载已制作的 H5/讲稿包，录音到成品的自动化链路仍是假设。
