## 讲稿处理模式

| 输入状态 | 默认处理 | 发布验收 |
| --- | --- | --- |
| 已定稿的致辞、演讲或会议发言 | 锁定原文。按投屏节奏分页，长段可在原标点处拆成阅读段。停顿、指屏和翻页提示放入独立字段 | 按页序拼接手机稿，与原正文逐字符比对。校验人称、数字、称谓、时间、标点、首尾句和段序；差异为零 |
| 未定稿的逐字稿、采访或课程原料 | 按教学目标编写口语稿，保留依据和审阅状态，交讲师确认 | 实际朗读、计时、检查事实和操作，再发布 |
| 已定稿且讲者另需精简或重写 | 从锁定原文建立可对照的新分支，先展示改动 | 由讲者确认目标版本后发布，旧稿可回查 |

平台草稿应记录稿件处理模式、正文与元信息范围、原文指纹、页段映射。以上规则同时适用于人工、外部导入和内置 AI。识别到「已定稿」时直接选原文模式。发布前根据模式选择校验。舞台画面可用短标题、视觉关系和重点语句，原文模式的逐字约束作用于讲师正文。编辑记录与查核过程留在工作区。

制课顺序以讲稿为准。先确认可讲正文，再拆投屏页纲和点按步骤，最后装配画面、动画与手机备注。

## 发布会视觉流程

1. **先写舞台画面脚本。** 明确听众、场合、屏幕比例和叙事转折。每页只定一个主视觉任务，先画封面、核心转折和结束页，再搭完整页序。
2. **让一条视觉线索贯穿。** 开场要有辨识度，转折要让关系一眼可见，收尾呼应主题。用同一套字阶、留白、色彩和纹理控制全场。图片以演讲内容为依据，使用实图时核对使用权；概念图用来表达主题和关系。
3. **按内容换构图。** 开场可大字和主画面同框，回忆用留白与年份，核心变化用对照，产业用场景，承诺用清晰的层级。观众屏优先大字和轮廓清楚的主视觉，详细叙述交给手机稿。小字、卡片和网页导航仅在承担明确任务时使用。
4. **先评 3 张关键页，再做余页。** 用一套可见的高保真设计验证字体、可读性、背景亮度与主视觉。比较实渲染结果；标题拥挤、视觉抢字、素材错配或页面重复时逐页修。
5. **按实际环境放行。** 16:9 浏览器检查全部画面、中文字体、裁切、资源切换与手机页稿。上台前在目标投影或 LED 上从后排检查字号、明暗层次和黑边，并做一次现场全流程排练。记录实测条件，作为下一场复用标准。

## 根据文稿制作配图

默认由 Codex 从文稿提取每页要表达的主题、人物或场景、关系与视觉重点。先做封面、转折和结尾的配图方案，确定构图和留白，再补齐其余页面。生成任务只需视觉简报，讲师原文继续留在备注与本地工作区。

- **有可靠实图时优先复用。** 从用户提供的 Markdown、图片和资料中选择能支撑讲述的素材，核对可用范围。需要看清细节时裁取关键区域，补上原生文字标注。
- **需要原创视觉时用 Codex 生成。** 适合封面、主题背景、抽象意象和概念场景。按投屏比例约束文字安全区、明暗和构图。生成图片里的场景按概念图使用，真实人物、现场、案例证据和数据以用户提供或核实的资料为依据。
- **文字、数字、图表与关系图由 H5 渲染。** 字号和排版可修改，内容可逐项核对。选定素材保存在课件包内，正式播放使用本地资源。

## 字体与入场动画

投屏主标题优先试重字重简体宋体，核对常用字、专名和标点。书法字体用于少数短句或结束页，配合主标题和正文字体形成层级。字体从作者或维护方取得，检查字形覆盖、授权和离线加载。打包子集时遵守保留字体名称规则并随包保留许可证。 [思源宋体](https://github.com/adobe-fonts/source-han-serif) · [马善政楷书](https://github.com/googlefonts/mashanzheng)

入场动画在切页时触发。主标题约半秒淡入并微微上移，信息分两到三次出现，关键对照允许用连线强调关系。保持背景稳定，遵从系统减少动态效果设置。按正常播放、回翻、手机遥控和减少动态效果分别检查。 


本次《让连接更有价值》示例以「通信的路 → 数据的路」组织 7 张舞台画面。封面以暖铜光路进入山谷；回忆页把光线压低；产业页以概念场景配合讲话；结尾让路径收束。正文 16 段，手机与离线稿均已逐字比对。实际会场大屏验收待进行。

## 点击触发与可编辑性

将切页动效与对象的点按出现分别配置。默认只在讲述顺序需要时设置点击展开。同一点击组可带出多个对象，演讲者按一次「下一步」才进入下一组。翻到该页时先显示第一组，等待时内容不自行出现。上一步可收回一组，刷新和恢复按已确认的步骤还原。

当前用独立配置记录对象、步骤、效果，由模板生成课件，Codex 可以按讲者要求直接修改。发布时校验对象存在、步骤连续、公开画面与手机指令对应。自定义 HTML 适配时由作者标记可控制的对象。

工作台的后续编辑能力可先做小面板：选对象 → 选「点击时出现」或「与上一项一起出现」→ 拖动顺序 → 预览 → 发布新修订。首版用受控模板内已标识的对象，保留当前演示协议。参考 [Keynote 的构件顺序与时间设置](https://support.apple.com/guide/keynote/change-build-order-and-timing-tan3ad5f8d82/mac)。
