## 2. 工程选型依据

- **保留 POST 与 SSE。** SSE 适合服务端向浏览器推送状态，浏览器可在连接关闭后重连。应用层仍负责会话绑定、快照、新旧状态判断和禁用过期控制。切换传输需有可复现的容量或延迟证据。 [MDN SSE](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)
- **发布包与草稿结构分开。** JSON Schema 用于形状与约束，运行时还需校验页稿引用、权限、布局和素材。模型的结构化输出可减轻解析负担，语义、事实和完整性仍由流水线和讲师审阅。一家服务商支持的 Schema 子集不能直接当作平台协议。 [JSON Schema](https://json-schema.org/understanding-json-schema/about) · [结构化输出示例](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)
- **维持 H5 沙箱并验证直接访问。** Opaque origin 和 iframe sandbox 有独立边界，需考虑用户直接打开资源、重定向、网络探测与伪造消息。ZIP 输入需限制路径、压缩与解压规模，防止 ZIP bomb 等。 [MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe) · [MDN postMessage](https://developer.mozilla.org/en-US/docs/Web/API/Window/postMessage) · [OWASP 文件上传](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)
- **先验证 Windows 便携交付，再判断外壳。** Electron 有预构建运行时及打包工具，现有 Node 栈可作为适配起点；Tauri 提供 Windows 安装包，需核对 WebView2 部署和外部运行进程策略。如果便携体验成为阻力，用两种方案各做小验证，测包大小、冷启动、断网安装、权限、签名、更新和数据保留。 [Electron 打包](https://www.electronjs.org/docs/latest/tutorial/application-distribution) · [Tauri Windows 安装](https://v2.tauri.app/distribute/windows-installer/) · [Tauri Windows 签名](https://v2.tauri.app/distribute/sign/windows/)
- **旧 PPT 迁移是单独研究。** PowerPoint 可导出固定格式，PresentationML 有独立 NotesSlide 结构。可以在样本上比较静态承载、提取备注配图、重点页重建。需要覆盖隐藏页、动画、视频、字体、公式和缺稿，逐页核对；不能由格式能力推断任意 PPTX 的还原率。 [PowerPoint 导出](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentation.exportasfixedformat) · [NotesSlide](https://learn.microsoft.com/en-us/office/open-xml/presentation/working-with-notes-slides)

## 4. 下一轮优先验证的问题

| 要证实的假设 | 实验方法 | 输出 |
| --- | --- | --- |
| 用户无需协助也能现场开讲 | 新 Windows 用户按使用说明打开，导入、切课、扫码、断外网演练，再升级重开 | 时间线、求助次数、失败发生在哪一步、连接诊断是否可行动 |
| 模板能让不同主题达到同等可读性 | 同主题套用两门差异大的课，抽查封面、知识、图表、案例、练习、总结，以教室投影和手机读稿验收 | 布局异常、主题是否要变、每种页型手工返工量 |
| 制课确实更省人 | 同一个短单元跑当前手工流程与工作台流程，记录审核、重写、修图、排练及模型费用 | 总耗时和分项成本；错误和返工量 |
| 长课瓶颈可定位 | 基准 237 页拆包，研究样本另取 100、300、500、1000 页；分别控制图/媒体体积、章节数、备注长度 | 启动、跳转、手机初载、恢复、内存、导入、备份与异常明细 |
| 值得做眼镜 | 确定机型后用同段真实讲稿对照手机和眼镜。记录低头次数、漏句、停顿、可读性、疲劳和断连 | 需求和可用性结论。语音跟稿、自动翻页分别立项 |

长课成本按准备、普通页校验、异常页修复、互动页重建、补稿审稿、媒体和整课排练分项估算。AI 成本计入实际输入/输出、重试、配图及人工复核。形成样本分布前，页面上限、固定单页价格与商业预测均留空。
