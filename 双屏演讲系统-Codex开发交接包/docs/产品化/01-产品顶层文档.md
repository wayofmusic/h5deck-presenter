## 1. 产品定位

为需要反复授课或演讲的独立讲师提供一套工作台。讲师把已有 Markdown、逐字稿或结构化大纲做成可编辑的 H5 课件，为每一页配独立讲稿，在电脑投屏，在手机看稿和控制。做完的课可备份、复用，也可输出给同事或学员使用。

首位用户是项目发起人，优先解决真实课程的制课、改稿和上台。个人使用跑通后，再邀请少量讲师用自己的材料试用。公开推广、定价和商业模式由真实复用需求决定。

| 用户任务 | 今天的阻力 | 产品应提供的结果 |
| --- | --- | --- |
| 从现有资料备课 | 逐字稿很长，画面和讲稿手工拆分，修订容易错页 | 导入后有章节大纲和逐页草稿，可改、可对照、可定稿 |
| 复用以前做的课 | 文件、图片、讲稿和工具分散 | 一门课一个入口，带版本、资产、备份和还原 |
| 站上讲台 | 现场要切窗口、找讲稿、担心手机失联 | 大屏与私有手机讲稿同步，失联时电脑继续，重新配对有明确操作 |
| 发给他人 | 工作底稿、私稿和交付文件易混发 | 学员版和讲师版分别导出，接收者能从单一入口打开 |

## 2. 已有基线与首版边界

v0.2 已有本地内容库、.h5deck v1、SDK、扫码配对、逐页讲稿、渐进展开、互动状态、双向控制、黑屏、计时和单机接管。已有 Windows 便携 ZIP。两部小米 Android 手机的历史成功反馈属于 v0.1，v0.2 兼容性按实际设备重新认定。

Vibe Coding r1 已做成 12 个单元、237 页，逐单元通过浏览器验证。这是拆分制作和加载的样本。首批要另外验证课程级导航、切换时的手机体验，以及场次持续运行。上一轮视觉与交付清理有制作源，正式 r2 内容包尚未形成，按独立内容发布任务记录。 [平台状态](../../STATUS.md) · [课程交付记录](../../课程交付-20261030.md)

| 优先级 | 范围 | 用户获得什么 |
| --- | --- | --- |
| P0 私测 | Windows 本地工作台、课件库、备注编辑、新修订、备份恢复、排练和现场连接 | 选一套老课，从改一页到现场使用，再迁移到另一台电脑 |

| 假设池 | 多天续讲、几百页单包、PPTX/WPS 迁移、音频自动转写、语音跟稿、AI 眼镜、公网与多人、原生桌面安装器 | 达到各自的验证门槛后再纳入实施 |

两种生成入口均是目标，实施顺序先走通内容标准与手工修改，再接产品内模型。逐字稿优先接用户提供的文本；导入已制作的自定义 H5 可继续适配，工作台首版只提供预览、改稿与版本管理。 [已有内容标准](../../03-标准内容包制作指南.md) · [假设池](../HYPOTHESIS-POOL.md)

## 3. 关键体验

1. **打开工作台。** 第一屏给出最近的课程、当前版本和「新建课程」「导入课件」。演讲配置、网卡诊断与维护入口在用户需要时出现。
2. **备课。** 给出目标听众、学习结果、时长和资料，先审大纲再分页。编辑区包含页目录、实际投屏预览和独立备注。缺稿、缺图和待核实的事实有定位信息。讲师可更改某页的模板、配图、文字、讲稿和互动。
3. **排练。** 选定已发布版本，预览观众和手机两端，确认计时、章节跳转、字号和配对。排练与正式场次各有独立状态，排练可从指定页开始。
4. **上台。** 大屏显示干净的 16:9 课件。手机显示当前页完整逐字稿、下一页标题和可单手操作的控制。分步展开与直接翻页分开，读到末尾继续停留当前页；断线时状态醒目，电脑能接管，恢复先追上当前画面。
5. **交付与复用。** 讲师版可含 .h5deck、逐字稿和必要操作说明。学员版只含适合学员的画面、练习和资料。发布时显示明确清单，生产底稿、测试记录、日志、配对信息和原始附件由内部工作区保管。

## 4. 内容视觉与可读性

主题属于课件层，同一个主题可换内容，同一份内容可切主题。首个主题以墨青、暖矿物灰和克制的铜色为方向。代码连线、网格、工作流节点等低对比纹理主要放在边缘，正文用安静底面。封面、知识、案例、图示、练习及总结有不同构图；课程图片优先从已授权的 Markdown 资料中选可读的图，必要时转成原生可编辑图示。只作为装饰的图不应盖住标题或正文。每个主题评审投影距离、低亮度、字号、对比、溢出、中文换行和互动状态。

手机和工作台以 WCAG 2.2 AA 相关条目为基础，正文对比度至少 4.5:1、大字至少 3:1，主要现场控制目标至少 44×44 CSS px，包含清楚的焦点、键盘路径和连接状态文字。手机稿件支持大字和 320 CSS px 宽度下重排。投影易读性额外做真实环境验证。 [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)

已定稿发言默认保留原文；发布会主题需单独完成视觉方案和大屏验收。 [讲稿保真与舞台交付标准](05-讲稿保真与舞台交付标准.md)

## 5. 数据、信任与交付原则

- 默认本地建课、存稿、配对和演讲。使用云模型前，展示服务商和将发送的资料范围，由用户确认。断外网仍能使用已发布课件，现场不依赖 AI。
- 公开画面、私有讲稿、编辑源、场次记录和凭据分开。学员导出单独生成。讲师包是可交付文件，收件人可解包读到讲稿，导出界面须明示其适用对象。
- 原始逐字稿保留，对含糊转写、缺出处的数据与他人经历标待核对。生成稿有修改和确认流程；发布时只带必要的引用、归属与课堂说明。
- 导入、修改与发布建立新修订；运行中的场次锁定版本。升级和恢复先核验，再切换，备份不含会话凭据或模型密钥。
- 试用统计默认用本地记录和受访者反馈。推广以前明确支持的设备、网络、素材使用条件与升级责任。

## 6. 怎么判断做成了

以下是私测候选目标，先建立实际基线，再冻结指标。

| 指标 | 口径与目标 |
| --- | --- |
| 核心完成率 | 5 位试用者中至少 4 位，用自己的材料独立完成导入或制课、改一页稿、扫码并演示 10 分钟。记录阻塞和求助 |
| 备课节省 | 对同一份 10–20 页真实材料，记录从导入到「排练后愿意直接使用」的人工时间，包含审稿和修图。与现有流程做配对比较，中位数目标减少 30% |
| 现场成功 | 核心路径至少有两次真实课堂或演讲成功，包含一次连续 60 分钟。手机断开可由电脑继续，讲稿错页、误翻和私稿泄漏为放行阻断项 |
| 交付成功 | 新环境从交付包启动、导入、手机配对、升级与恢复。接收者无需开发工具、命令行或口头指导 |
| 复用意愿 | 记录试用者是否愿意带第二套真实内容回来、实际复用了什么，以及替换现有方法的代价 |
