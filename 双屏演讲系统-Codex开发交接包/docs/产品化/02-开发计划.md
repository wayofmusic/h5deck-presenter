## 1. 实施顺序

先建立稳定基线，再做一条能自助完成的用户路径。阶段验收以发布候选包和真实操作为准。工作量是单人实现的初估，包含各阶段内部验证，真实设备、用户反馈及模型接入等待单独计。A0 完成后重估。

| 阶段 | 依赖 | 实施内容 | 放行证据 | 粗估 |
| --- | --- | --- | --- | --- |
| A0 基线与安全复验 | 无 | 固化 v0.2 源码基线、构建产物、样例和可恢复的数据快照；定位本机启动；核对现场权限、断线接管、风险矩阵 | 从独立目录重现 v0.2；原 32 页和两类标准包可用；列出阻断项和真机缺口 | 2–4 工作日 |
| A1 可靠演讲与课程库 | A0 | 课程卡、导入预检、版本列表、逐页改稿、按场次锁版本、备份恢复、演讲前检查、连接诊断 | 老包导入→改一页→发布新修订→双端一致→回退→在另一目录恢复。断外网可演示，故障时电脑可接管 | 5–9 工作日 |
| A2 标准化制课 | A1 | 规定范围的 Markdown/文本和结构化 JSON 导入，草稿编辑，受控主题和组件，预览、排练、发布，按对象导出 | 两门不同主题真实课完成制课，标题、资源、讲稿和互动通过审阅；能在空白环境导入成品包 | 7–12 工作日 |
| A3 AI 小规模验证 | A2 + 模型接入细节 | 同一标准接一个模型接口，分阶段和分页生成，资料范围确认，人工确认与费用约束 | 用同一短课对比备课耗时与质量；取消、失败、重试、缺资料和冲突能恢复。保留无模型的制课路径 | 4–8 工作日 |
| A4 交付与试用 | A1 开始打磨，A2 后放行离线试用 | 一键启动和退出、干净 Windows、数据迁移、支持清单、真实演讲及小范围试用 | 新环境独立启动到上台、升级与恢复；达成产品验收线。A3 未通过时按离线范围交付 | 3–6 工作日 + 试用窗口 |

按依赖分批实施。先走 A0→A1，一次迭代用一个真实课件改一页稿并完成双端排练。r2 课程视觉和成品内容清理属于内容发布任务，可把选定的几页用作 A2 主题验收样本，软件计划与 237 页内容制作分别估算。

## 2. 分层与兼容

| 层 | 复用现状 | 拟增能力与约束 |
| --- | --- | --- |
| 演示内核 | `core/state.mjs` 与现有 POST/SSE，稳定 page/step、计时、黑屏和单机接管 | 服务端继续负责顺序，客户端恢复先读快照。先测再优化；多次点击、命令过期、时钟偏差、并发交替控制有覆盖 |
| 会话与权限 | `server/index.mjs`、本机控制、单主控配对、旧版命令 | 场次锁定 `deckId@revision`，编辑和导入走独立流程。保持同一课件内稳定跳转，跨独立 .h5deck 切换按现有重新配对规则，并在界面提示 |
| 课件库 | `server/content-library.mjs`、v1 校验和存储 | 库条目、草稿、已发布修订分开。版本内容不可变。导入备份先在临时区校验再提交，有失败恢复 |
| 内容制作 | `content-templates/`、`standards/`、`packaging/content-cli.mjs` | 新草稿 Schema、受控编译器、主题组件和质量检查。产物继续用 v1，复用现有 SDK 与校验 |
| 界面 | `clients/host/`、`clients/presenter/`、`clients/display/` | 工作台新增课件库、编辑、发布和排练入口；手机和大屏保持各自职责。以当前方案实现首个完整纵切，新增前端栈需证明维护收益 |
| 发行 | `packaging/launch.mjs`、`packaging/release.mjs`、Windows 运行时 | 成品发布与开发交接分离，运行时与可迁移用户数据分开。发版白名单、依赖许可、版本记录和内部证据由流水线管理 |

阶段内遵循三条兼容约束：旧 v1 内容包可继续导入和演示；现有课件 ID、页 ID 与备注映射不随界面更新改写；发布新修订不会改变正在演讲的场次。若需要协议升级，先提供可检测的版本协商、迁移备份和兼容回归。当前库是多个独立包，课程聚合先实现分组和排序入口；同一场次跨包连续播放另做验证。

## 3. 内容和版本设计

| 对象 | 最小字段与关系 | 生命周期 |
| --- | --- | --- |
| 课程 | `courseId`、标题、可选简介、单元顺序、当前草稿与发布引用 | 本地组织，课件库可把多个 v1 包归到同一课程 |
| 草稿 | `draftVersion`、`schemaVersion`、主题版本、章节、页面、资产引用、私有依据索引 | 自动保存；保存带基准修订，防止两个窗口静默覆盖。保存失败可重试 |
| 页面 | 稳定 `slideId`、版式类型、公开文案和媒体、渐进组、互动配置、建议时长 | 重排保留 ID；复制分配新 ID；删除给出备注和素材影响 |
| 私有讲稿 | `slideId`、段落 ID 和文本、现场提示、待核对标记 | 与同版本页面绑定；清除和编辑有回退路径 |
| 已发布修订 | `deckId@revision`、模板/编译版本、包、校验结果 | 同修订同内容，冲突返回可操作提示；发布完成后才可被选择 |
| 场次 | `sessionId`、锁定修订、当前页、步骤、计时、配对 | 排练和正式场次各自初始化。手机凭据独立于备份；跨天断点留在假设池 |

A1 备注编辑支持 v1 包：从已发布包复制工作副本，只改私有备注与必要修订字段；保留公开资源、页序、步骤和互动。原 32 页旧适配版继续演示，其可编辑迁移另按格式处理。A2 受控模板草稿允许编辑画面，第三方自定义 H5 仍按原 SDK 维护其代码。

候选导入支持 UTF-8 Markdown、纯文本与版本化 JSON。Markdown 第一版明确标题层级、页面分隔、备注区和包内图片路径。纯文本先进入人工拆分或辅助大纲；旧文档、PDF、音频和 PPTX 另行评估。外部 AI 获得 Schema、最小示例和失败报告。导入预览显示章节、页数、缺稿、缺图、无法识别的块，按页定位。输入材料中的文字只作为课程数据；脚本、链接和命令不得触发导入器执行外部动作。

发布流程：校验草稿 → 固定模板编译公开画面 → 单独生成私有讲稿 → 检查资源与互动 → 复用 .h5deck 校验器 → 临时区写入并验证 → 原子提交版本引用。资源、数据文件和索引的提交顺序应可从中断恢复。首轮按现有文件库实现，只有出现并发写入或索引性能瓶颈，再评估存储替换。

分发输出分三种：

- **软件**是一个 Windows 便携包，包含必要运行时、启动入口、简要帮助和匿名示例。
- **课程**按用途生成一个讲师 ZIP 或学员 ZIP。讲师版本包含演讲内容包与可选独立讲稿；学员版另生成可读画面和练习。学员版解包检查讲稿、原始材料和凭据缺席。
- **备份**含用户选择的草稿、发布版、素材和课程索引，用于恢复或迁移。提示私有内容。还原前检查冲突、磁盘空间和兼容版本，恢复错误时原库仍能打开。

## 4. 内置 AI 验证计划

内置和外部生成共享课程草稿标准。首个模型验证选择一节 10–20 页真实课程，已确认默认本地，用户主动启用后可使用自带密钥的云模型。实现前确定服务商、资料可发送范围、凭据存储和预算。外部生成由用户在所选工具中完成，工作台只处理结果文件。

内置生成按「需求与资料 → 确认大纲 → 按单元分段生成 → 页面与讲稿审阅 → 发布」执行。用任务 ID 与输入版本记录每次分段结果；可取消、重试失败段和按页重做。模型输出通过 Schema 与引用校验后进入草稿区，语义、讲述口吻和事实仍要审阅。未经确认的内容保留待核对标记，发布策略区分警告和阻断。单页重做时保留旧稿供对比，已发布版本始终可回退。

发送前显示服务商、资料范围和预计消耗；执行按设定上限停止，展示已用量和失败重试成本。密钥只存于选定凭据位置，禁止进入课件、日志、备份和手机端。默认不向模型自动发送全文、私有附件或他人案例资料。供应商不可用时可继续手工编辑和演讲。

## 5. 验收矩阵

下面的性能值是候选目标。A0 固定 Windows 配置、手机、浏览器、网络、课件页数与媒体体积后测基线。记录 p50/p95、样本量和失败率。投屏画面实际应用与手机稿完成渲染分别测量，跨端时钟先校准或用同一采集端测量。

| 验收项 | 主要场景 | 候选放行标准 |
| --- | --- | --- |
| 同步 | 普通翻页、展开/回退、跳页、双端交替、互动刷新、黑屏、计时 | 目录、投屏和手机的 slideId/步骤一致；私有讲稿只在授权端；同 Wi-Fi 普通页手机指令到投屏应用 p95 ≤ 300ms，手机讲稿 p95 ≤ 500ms。至少 200 次代表性命令计样本 |
| 恢复 | 锁屏/前台、断网、热点、刷新、电脑接管、服务重启、手机撤销 | 链路可达后 p95 ≤ 3 秒恢复至当前快照，统计成功率。期间旧指令不重放，旧凭据失效，电脑可继续演示。服务重启按现有显式接管路径单列计时 |
| 真实环境 | Redmi K70 Pro Chrome/Edge、Mi 10 Pro 系统浏览器、同 Wi-Fi、手机热点、隔离 Wi-Fi、无互联网 | 核心组合真机实测；隔离网络给可执行提示。30 分钟计时和 60 分钟连续运行按真实时间记录。设备支持声明以通过项为准 |
| 内容质量 | 标准模板两门差异课程、自定义包、237 页拆包、缺资源、长中文、字号与纹理 | 页稿对应全量核对；首发模板在 16:9 和代表性低亮度投影下可读，脚本错误、空白与关键内容裁切为阻断 |
| 安全 | 恶意 ZIP、文件名与链接、直接打开内容 HTML、伪造桥接、跨站访问、无授权稿件、共享导出 | 覆盖压缩/解压限额、路径穿越、同源/CSRF、Host/Origin、控制撤销和私稿边界；未授权操作被拒绝，学员产物无私稿。具体风险在隔离环境确认 |
| 升级与持久化 | 干净 Windows、无管理员安装、中文路径、端口占用、进程残留、磁盘满、断电/中断、同修订冲突 | 用户按说明启动与退出；失败不损坏原库；从成品 ZIP 安装或解压后完成导入、备份、恢复和升级回退 |
| 使用效果 | 真实材料、第二次复用、人工和 AI 两条路径 | 达到产品顶层文档的完成率、现场、备课与迁移目标，记录失败路径和修正 |

A0 同时做本地威胁建模。明确共享局域网 HTTP 的边界、默认监听地址、配对开启时机、过期与限流；测试访客网络、LAN 请求与本机权限隔离。审查自定义 HTML 直接访问时的 HTTP sandbox/CSP 或独立来源方案，根据测试选择兼容改动。模型权限及外发只在 A3 设计冻结后进入测试。规模验证区分库总页数、单包大小、当前活跃单元、媒体与讲稿传输。

## 6. 交付和回退

- A0 建立可审阅的源码基线。现有 Git 无提交，先核对忽略项和私有文件，记录基线版本与可重建步骤。仅保留必要构建产物作证据。源素材、真实讲稿、日志、密钥和运行库数据分别管理。
- 每阶段保留变更说明、复现实验、设备与测量条件。面向用户的课程包和软件包按发布清单生成，内部验证记录由团队留存。
- 发版从真正解压的发行包执行整套主流程。测试配置、备份和迁移都用隔离数据目录。遇到错页、未经授权稿件访问、版本损坏或无法回退时，停发该候选并恢复上一可用版本。
- 对外试用前核对运行时与依赖许可、课件与素材的发布权、签名与安全提示、下载完整性及支持说明。留存上一版本和数据快照，回退后验证旧版能读该数据或能还原原快照。
