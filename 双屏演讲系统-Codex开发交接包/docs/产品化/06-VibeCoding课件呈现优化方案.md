# Vibe Coding 两天训战营 PPT 呈现优化方案

2026-11-05 · 待评审  
关联 [课件视觉与现场讲稿改进计划](04-课件视觉与现场讲稿改进计划.md) · [讲稿保真与舞台交付标准](05-讲稿保真与舞台交付标准.md)

## 目标和基线

现有课程分 12 个单元，共 237 页、510 个展开状态，包含 116 页条目布局。观众最常看到标题和若干同权重的条目，少数关键关系、真实界面和操作变化还没有成为画面主体。计划把现有两天课程改成适合现场投屏的系统课件。大屏帮助学员看懂和跟上，手机保留讲师能直接说的完整逐页稿。

发布会版的经验用于封面、转折、核心图和路演收束。长时间授课以暖灰知识页承载细节，深墨青用在章节转折和演示重点，保证阅读节奏。12 个单元与原有讲稿映射作为重构基线。增删、拆并页面须同步维护页 ID 与备注映射，记录调整原因。

## 视觉系统

| 页型 | 大屏如何呈现 | 优先内容 |
| --- | --- | --- |
| 开场和换章 | 墨青舞台画面、宋体短标题、沿边缘延展的低对比代码或路径纹理 | 两天课程地图、单元进入前的学习任务 |
| 知识和方法 | 暖矿物灰底，原生关系图、路径图、对照图和结论标题 | 技术分层、版本关系、任务依赖与里程碑 |
| 案例和演示 | 真实界面放大，只圈当前操作或对照前后结果；命令、字段、结果单独排版 | 第一次制作、计算器调试、代码与运行证据 |
| 练习 | 大字标时间，清楚显示任务、提交物和完成标准；连续练习保留计时与稳定画面 | 独立排查、小组任务、同伴复验 |
| 小测与反馈 | 题目和可点击选项先出现，选择后才出反馈；说明依据放到手机稿 | 概念判断、现场提问、项目检查 |
| 路演和总结 | 以作品、证据和行动收束。用时间轴讲清八分钟路演的安排 | 结果展示、点评、下一步 |

标题以可离线加载的简体重宋体为起点，操作界面和正文字体优先辨识度。发布会的书法字可用于少数有表达需要的开场或收束。知识与练习页保持明暗稳定，不以纹理填满空白。颜色承担有限的提示职责，同一含义同时用文字或图形标明。设计稿按 16:9 制作，关键区域留出屏幕安全边距。

## 制作顺序

逐字稿定稿 → PPT 页纲和动画脚本 → 素材装配与双屏试讲。以单元为制作单位，每个单元都按这个顺序走。

| 阶段 | 做什么 | 交出什么 |
| --- | --- | --- |
| 1 优化逐字稿 | 对照原逐字稿、Markdown 和已有课程，核对事实、案例、术语和操作。按上课顺序写完整可讲的稿，保留例子、解释、练习和转场。把讲师说的话与提问、等待、演示等提示分开。先朗读，分别估算讲解、操作和练习用时 | 一份按讲述段落组织、可独立试讲的讲师稿。确认能顺畅说完，才进入拆页 |
| 2 出 PPT 框架和动画 | 从讲述段落拆页，给每页编号，记录对应稿段、画面要点、页型、所需素材。写清进页先显示什么，讲到哪一句按一下，出现哪个对象，哪一步翻页。用低保真页纲走完一遍 | 逐页框架和点按清单，讲稿与页码、步骤有明确对应 |
| 3 装配与试讲 | 按已确认的框架挑原图、生成插图、制作原生图示、套版式、接入动画和手机备注。电脑投屏、手机看稿跑完样段，再核对发布包 | 可导入的 H5 课件、完整逐页备注与课堂练习 |

例如，调试段先写好「输入二和三，先猜结果，再点计算，记录屏幕显示了什么」。随后定为一页，首屏显示输入和提问，点按后展示实际结果，讲师再布置记录。最后装配计算器界面、对照区域、点按动作和手机提示。

## 素材与画面装配

- STAR 矩阵保留两个坐标轴和四象限的关系，以及必要归属。实际界面优先截取关键区域，再用原生文字标注。
- 用 Codex 按框架生成章节图、背景纹理或概念插图。项目实测、成果和数字用已有证据，流程、关系和数据由 H5 绘制。
- 舞台画面、可讲正文、现场操作提示和内部依据分别维护。定稿的正式发言保留原文，已审阅的课程讲稿作为拆页依据。

## 点按展开和双屏节奏

- 先显示当前页标题与第一组内容。需要按顺序讲的结构、推演或结果用「下一步」逐组出现。回退时能收回一组，复位后按当前状态恢复。
- 开场、练习说明、阅读表格和大多数案例背景进页即完整显示。展开用于观察、提问和讲解转折。避免为了动效让学员多等一拍。
- 选 3 种稳定效果作为模板默认配置，即淡入、轻移入和连线出现。动画节奏与步骤独立，遵循减少动态效果设置。
- 手机以当前页完整讲稿为主，必要时用独立提示注明哪一步展开、指哪里、等多久。操作词与大屏按钮一致。讲稿读到末尾由讲师主动翻页。

## 分批实施

| 批次 | 范围 | 要定下来的结果 |
| --- | --- | --- |
| 1 标准样段 | 先从第 07 单元调试段做一段连贯逐字稿，再拆成 PPT 页纲和点按步骤。讲稿与框架定后，补 01 开营、03 STAR、05 技术地图、12 路演的代表页，预计合计 10–12 页 | 先试讲稿，再核对页纲和动画，装配后与旧画面对照 |
| 2 第一天 | 01–06，优先处理入门项目、选场景、技术地图和里程碑 | 做出一条从理解到动手的授课节奏，普通知识页批量套经验证的模板，关键演示逐页设计 |
| 3 第二天 | 07–12，优先处理调试、并行、封装、项目拆解和路演 | 能复用已验证的实操、互动、判断与计时样式，案例图与讲稿逐页审阅 |
| 4 成品交付 | 按 12 单元回读讲稿、页纲与动画，整理统一入口、讲师稿、练习与使用说明 | 形成一个正式课程 ZIP。成品和内部对照记录分开，讲师与学员使用的内容各有交付清单 |

第一批用实际制作用时估算全量。分开记录普通模板页、截图证据页、交互页和讲稿复核的耗时，保留对单元难度和素材质量的判断。两天课包含独立操作与小组讨论，讲课时间以现场试讲校准。

## 验收

- **后排可读。** 用实际 16:9 投影检查标题、示例界面、代码、轴线和图例。关键信息能在短时间内被复述，背景明暗与字号不干扰识别。
- **操作可跟。** 学员能按屏幕和讲稿完成一个代表性练习，并说清提交物和完成标准。现场提示帮助讲师完成切页与等待，记录卡顿和临时改词。
- **页稿对应。** 逐单元遍历页面和展开，检查手机对应正文、互动、计时和恢复。原稿事实、图表数据和素材使用范围经过核对。
- **交付可用。** 在独立环境从成品包打开课程和练习，核对资源、讲稿与必要说明。正式发放前以讲师的实际试讲反馈为放行依据。
