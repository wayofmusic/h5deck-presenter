# H5Deck 课件视觉与现场讲稿改进计划

2026-11-05 · 待评审  
适用于 [产品顶层文档](01-产品顶层文档.md) 的制课体验和 [开发计划](02-开发计划.md) 的 A2 内容制作、A3 AI 生成验证。已定稿的正式发言默认保留原文，细则见 [讲稿保真与舞台交付标准](05-讲稿保真与舞台交付标准.md)。

## 1. 目标和现状

产品要从一份逐字稿或原素材产出一套可直接上台的 H5 PPT。观众看画面、关系和关键例子。讲师在手机上看到当前页可直接说的完整口语稿，以及清楚分开的操作提示。内容经过讲师排练后可按现有 .h5deck 格式交付。

这次读取了现有 Vibe Coding r1 的 12 个课件源文件，统计页型和备注中的制作措辞，并抽查代表页、投屏截图和 Markdown 配图。237 页中有 116 页使用条目布局。按「原稿、原课、原讲、随包、本版、原附件、试制、审读」查到 96 页至少出现一处命中。96 是人工审阅线索，实际错误数要结合句意判断。

| 看到的问题 | 对现场的影响 | 解决方式 |
| --- | --- | --- |
| 五段路演时间分配做成等宽条目表，时间关系没有成为画面的重心 | 讲师需要逐项解释，学员难以扫出八分钟如何分配 | 改为分段计时轴，醒目标出每段时间与交付要求。适合查阅的页面继续用表格 |
| 「问题定义先回答……」一口气列多个抽象字段，示例靠后 | 听众要同时理解新词和操作，讲师要现场补具体情景 | 用同一输入和触发动作开场，随后把字段落到屏幕上的演示 |
| 「原附录把问题整理成 5W……本版直接用这些具体问题」进入口播 | 讲师读着读着跳到制作过程，打断课堂 | 依据与争议写在内部编辑记录。口播直接带学员重现问题。必要归属自然保留 |
| 渐进展开与讲稿段落没有明显节拍 | 容易提前念出还没展开的内容，演示时找回句子也费劲 | 为需要现场操作的段落标注对应步骤、指屏对象和动作时机。简单页只保留主稿 |

按口播检查的七项诊断，抽样命中四项：抽象词集中、具体场景偏少、书面节奏、先讲定义。另三项在抽样中没有足够依据判为普遍问题：金句过密、事实与判断边界薄弱、缺行动。现有课程的练习和边界提醒可以继续用，逐页改写时再核对。

## 2. 先做两类样本

| 顺序 | 素材与范围 | 主要验证 |
| --- | --- | --- |
| 1 培训课 | Vibe Coding 第 7 单元「调试与验证」第 11–18 页。保留调试链、计算器、实操、回归、同伴复验、清单、测验与收束 | 流程图和演示截图是否帮助理解；翻到哪一步就能讲到哪一步；学员能否按讲解复现；实操时段按原计划另计 |
| 2 正式致辞 | 《20261104 让连接更有价值 - 徐剑.docx》。20 个非空段落，约 2,460 字，纯文字正文。试做 6–8 页，时长按现场要求或实测语速确定 | 第一人称口吻和讲话情绪能否保留；画面能否突出少量关键信息；行业数据、个人经历、机构称谓和承诺能否准确保留 |

致辞可从「回到德阳、通信保障经历、数据与产业、落地与承诺、致谢」切分。首轮优先做忠实辅助版，正文保留讲话逻辑和关键原话，重点处理断句、停顿、长段和翻页。文章中的行业排名、服务规模等属于稿件陈述。用于对外版本前由讲者确认口径、来源和时间，未确认数据留在编辑区。照片、地图与品牌素材使用实际可提供和可发布的版本，缺素材时采用文字、路径图或关系图。样稿保留徐剑的发言身份，演讲者若变更，经历和承诺须重新归属。文档正文标注的活动日期为 2026-11-03，制作时以正文与活动方确认的日期为准。

## 3. 画面怎么改

每页先写清观众要带走的一句话，再选择支持它的视觉。具体做法参考多媒体学习中的重点提示与减少冗余，以及技术演示中的「主张标题 + 视觉证据」。这些研究给试做提供方向，课堂表现由本项目实测。 [Mayer 与 Fiorella](https://doi.org/10.1017/9781108894333.019) · [Garner 与 Alley 等](https://www.writing.engr.psu.edu/ae_comprehension.pdf)

| 页的任务 | 主画面 | 课上怎么用 |
| --- | --- | --- |
| 开场与章节转折 | 一句主张、少量标题和大留白；主题纹理靠边 | 一眼知道这一段要解决什么 |
| 方法与关系 | 流程、时间轴、关系图、错误与预期对照 | 按步骤展开，当前讲的部分高亮 |
| 案例与操作 | 放大的真实界面、命令、表单或截图局部；短标注贴近操作点 | 指给学员看按钮、数据和结果发生在哪 |
| 练习与结尾 | 时间、任务、提交物和完成标准作为主层级 | 学员低头练习后抬头能立刻找回要求 |

培训主题采用墨青、暖矿物灰与少量铜色。代码网格、连线和节点做低对比边缘纹理，标题与正文落在平静的底面，避开纯黑和纯白。致辞使用同一套可读性规则，可改成更克制的活动主题，用城市、通信链路和产业关系点题。

Markdown 原图先按「能讲清什么、事实是否准确、投影能否读清、可使用范围」筛选。像 STAR 矩阵适合保留坐标关系并放大，或用原生图形重绘并保留归属。带小字的操作截图可以裁取关键区域再标注。配图首先服务证据和操作，纹理负责氛围。按 16:9 真机预览、低亮度投影和后排可读性验收。正文与底面对比以 WCAG 2.2 AA 相关阈值作基础参考。 [W3C 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)

## 4. 讲稿怎么改

按单元先规划讲述线，再逐页写。每页给模型或编辑提供当前页画面、前后页、原材料片段、讲师风格与授课时长。保留原始逐字稿作为内部可追溯依据。将数据、原话、推断、争议点分开；正文只采用审阅通过的材料。教育演讲的实用方法是写给耳朵听，朗读时找长句、卡顿和不自然的停顿，再按实测时长修。 [Stanford Oral Communication Program](https://oralcommprogram.stanford.edu/presentation-and-delivery/paper-presentation) · [University of Mary Washington Speaking Intensive Program](https://academics.umw.edu/speaking/resources/handouts/using-a-script/)

| 备注结构 | 进入交付的内容 |
| --- | --- |
| 完整口语稿 | 讲师拿起就能说的句子。解释用日常动词和具体动作；需要连读的句子保持自然。按段分气口，篇幅用真实语速和页面动作估算 |
| 现场提示 | 单独显示动作，例如「展开第二步」「等学员输入」「指右侧结果」。与页 ID 和展开步骤关联。只在需要时设置 |
| 可选补充 | 独立的备用例子或解释，控制超时场次时可略过。优先保留主稿完整性 |
| 内部依据 | 源片段、转写疑问、图片权属、数字来源和审阅状态。留在工作区。讲师版只含可讲内容和必要操作提示，学员版按单独清单导出 |

用条件句和具体结果区分演示情境与已有事实。案例先讲发生了什么，再提炼判断。稿件里「接下来我们来深入探讨」「形成闭环」等通用句标记复核，按实际说法改。发布扫描针对「本版保留」「原稿这里」「随包附带」「待核对」等制作语境。课程内有实际用途的「软件测试」「先核对日志」和必要引用按句意保留。讲师风格可从用户自愿提供的 60–90 秒自然讲述或已认可段落提取，先用清晰自然的中性口语做基准。

### 同一页的文字样例

现有备注有一句「问题定义先回答：什么环境、谁受影响、怎样触发、预期什么、实际什么、出现频率怎样。」信息有用，但一次读六项，听众还不知道要观察哪个结果。

| 层 | 改后样例 |
| --- | --- |
| 大屏 | 标题「先把问题重现一次」。主体依次呈现「怎么操作 → 期望什么 → 实际发生什么」。右侧用计算器界面显示输入和结果区域 |
| 手机主稿 | 「同事说，‘我点保存没反应。’你能马上找到原因吗？先问他点了哪里。再问他原来以为会发生什么。我们现在用计算器试一次。选加法，第一个框填 2，第二个框空着。先说你希望它给什么提示。现在按下计算，看实际出来了什么。只出现过一次，就先记一次。现在把刚才的操作、预期和结果各写一行。」 |
| 现场提示 | 「点击计算，等学员观察。依次高亮操作、预期、结果。」 |
| 验收动作 | 学员复述输入和点击顺序，按同样步骤操作，并能指出预期与实际的区别 |

这个例子是试讲样稿，需用真实演示界面核对按钮和步骤再定稿。写作检查聚焦六条规则：用动作起句，抽象词跟实例，数字与经历保真，动作提示单独显示，跨页朗读，结尾给出可以执行的任务。

## 5. 用对照试讲选方案

同一材料保留现有版 A。画面优先做 B，讲稿优先做 C，再用合并版 D 跑一段完整的双屏试讲。时间紧时，只挑两页用 B/C 单变量比较，其余直接用 A/D。给不同评审者交换观看顺序，尽量减少看过内容后变熟的影响。建议 1 位讲师、2–3 位接近目标听众的人。小样本用于取舍与发现问题。

| 假设 | 怎么测 | 初始通过条件 |
| --- | --- | --- |
| H1 关系图、对照图比同一套列表更能讲清内容 | 用同一段讲稿看 A/B。看完 10 秒，问这页讲什么、下一步做什么。再记录读不清的标签与分心元素 | 试用者能准确复述主旨，理解表现至少不低于 A；大多数偏好 B 的画面，后排没有关键文字读不清 |
| H2 场景和动作带出来的讲稿更好讲 | 同画面读 A/C，记录需要临场改词、停下来重读和查找段落的次数；按实际说完的时长计 | 讲师自然度与可直接使用评分至少 4/5，改词、卡壳合计较 A 下降约 30%，实测时长满足场次要求 |
| H3 动作提示与展开同步能提高现场可控性 | 用 D 跑 6–8 分钟代表段落，覆盖翻页、逐步展开、停顿、演示、布置任务。练习计时另测 | 页稿错配、提前说到下一步和因提示误触翻页均为 0；学员能按稿中指令做出一个可复现记录 |
| H4 同一流程能服务正式发言 | 对致辞跑忠实辅助版，按不同叙事段试讲并计时，核对人称、称谓、承诺、数字、重要停顿 | 讲者或授权审阅人确认关键表述；听众能复述讲话主题。稿件用语、画面、时长适合活动 |

如 B 更好看但复述变差，回到信息层级和素材取舍。如 C 读得更快却遗漏事实，回到源片段和必讲清单。如 D 只在少量页改善，优先固定有效的页型和语句规则，继续复验问题页。

## 6. 实施顺序与产品化

1. **准备基线。** 选定调试 8 页，核对原材料和实际演示，记下页型、讲稿、计时和旧版表现。
2. **制作可导入样稿。** 先做两页视觉与讲稿对照，再完成连续段。用独立修订包交付样稿，可在现有服务里选择对比。稳定页 ID，逐步动作和手机备注逐项对照。
3. **试讲和改稿。** 从电脑投屏、手机看稿的真实路径走一遍，记录听众复述和讲师改词。使用正式致辞样本复验第二种场景。
4. **沉淀到 A2 与 A3。** A2 固化可切换主题、可复用页型、备注分层、逐步对应、人工预览与发布校验。A3 再将通过的讲稿和页面规则用于内置生成与外部结构化导入，并衡量单页返工时间。动作提示的细粒度结构优先放在草稿层，现有 .h5deck 先用已有段落和提示字段承载。
5. **按单元扩展。** 验收通过后按旧课件的常规页、图片页、演示与互动页分批转换。记录每类普通处理、人工修订和复验的实际耗时，再估 237 页的改版成本和排期。

第一轮交付物是两类可试讲样稿和独立的评审对照。正式课程包按成品白名单发布，保留课件、逐页讲稿、练习和必要说明。前后对照、测试结果和制作记录放在内部。


## 7. 首轮样稿记录

2026-11-05 已产出调试与验证 8 页、徐剑致辞 7 页的独立 .h5deck，并导入本机工作台。调试段保留三组输入、独立排查、同伴复验、清单和提问。致辞保留第一人称、活动日期与个人经历，试讲版暂不带未经核对的行业排名和服务规模。交付 ZIP 含两套课件、独立逐页讲稿、计算器练习和入口。

桌面 1600×900、移动视口 393×851 覆盖 15 页、21 个展开状态。验证了配对后的页稿对应、双端切换、计算器结果、清单、测验和公开/私有资源边界。对照用包存于工作区内部，A 是既有课件，B 用新画面和现有讲稿，C 保留原画面并替换两页讲稿。真实投影、现场朗读计时、听众复述与讲师反馈待收集。
