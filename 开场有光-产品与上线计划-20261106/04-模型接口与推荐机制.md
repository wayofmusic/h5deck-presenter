# 开场有光｜模型接口与推荐机制

2026-11-06 · 接口设计稿，当前尚未实现

用户已明确：软件是一套框架，可以调用不同模型来制作课件和清晰的逐字稿；模型允许自行接入，同时提供效果好的模型推荐。本文件把这项要求拆成可实施的产品能力。

## 1. 用户怎么接自己的模型

普通用户的路径：

1. 打开“设置 → 模型服务”，选择预置服务或“自定义兼容服务”。
2. 填写服务地址、API Key，获取模型列表；也可手填模型 ID。
3. 点击“测试连接”，看到鉴权、模型可用性、文字生成、结构化输出、图片理解等检测结果。
4. 选择“整场使用这个模型”，或分别指定结构规划、逐字稿、看图、页面制作和复核模型。
5. 新建项目生成三页样稿，查看结果、用量和修改记录；以后可替换模型。

云服务与本地服务都可配置。本地服务使用兼容协议时直接填本机地址；软件不会默认扫描网络或自动下载大型模型。

模型列表接口并非每家都实现，因此“手填模型 + 实际探测”始终保留。只会文字生成的模型仍能用于写稿；需要图片的任务会提示换模型，或提供可检查的文本提取替代流程。

## 2. 三层分开

| 层 | 管什么 | 怎样扩展 |
| --- | --- | --- |
| 服务连接器 | API 协议、鉴权、流式、错误、取消、用量归一化 | 开发者增加受控适配器 |
| 模型目录 | 服务商、模型 ID、上下文、图片、结构化输出、价格来源、验证状态 | 配置目录更新；用户可添加模型 |
| 任务配方 | 输入资料、提示词、输出结构、质量检查、局部重做 | 随软件版本管理，可单独迭代 |

一般新增兼容模型只需要配置。遇到新的原生协议才开发连接器。用户添加模型不会改变已有项目结构、内容包或演讲状态机。

首轮不允许任意下载的模型配置附带本机执行代码。外部连接器属于后续开发扩展机制，与“填地址接模型”区分。

## 3. 首轮协议范围

| 协议 | 首轮安排 | 验收重点 |
| --- | --- | --- |
| OpenAI Chat Completions 兼容协议 | 优先实现通用连接器；覆盖至少两家实际服务 | base URL 拼接、鉴权、流式、终止原因、JSON、图片、用量的差异 |
| Anthropic Messages | 首轮实现独立连接器 | 内容块、流式事件、思考参数、图片与结构化输出按实际 API 处理 |
| Responses | 适配接口预留，按真实服务需求新增 | 不能直接复用 Chat Completions 请求体或假设工具协议相同 |
| Gemini 原生 API | 扩展阶段接入，先冻结接口边界 | 模型列表、内容/图片格式、流式、错误与用量归一化 |
| 本地模型服务 | 通过已支持的兼容协议接入 | 实际能力探测、内存/速度提示、离线验证 |

“OpenAI 兼容”是协议类型，不代表所有能力都相同。预置列表为每个模型记录实际能力，连接测试按需要探测，避免向不支持的模型传入参数。

## 4. 内部接口草案

下面是接口责任示意，用来指导实现，不是现有软件可调用的 SDK：

```ts
interface ModelProvider {
  listModels(connection: Connection, signal: AbortSignal): Promise<ModelInfo[]>;
  probe(connection: Connection, modelId: string, signal: AbortSignal): Promise<CapabilityReport>;
  generate(request: GenerationRequest, signal: AbortSignal): AsyncIterable<GenerationEvent>;
}

type GenerationEvent =
  | { type: 'text-delta'; text: string }
  | { type: 'structured-output'; value: unknown }
  | { type: 'usage'; inputTokens?: number; outputTokens?: number; estimated?: boolean }
  | { type: 'warning'; code: string; message: string }
  | { type: 'done'; finishReason: string; requestId?: string };
```

GenerationRequest 包含任务类型、已选择资料、模型 ID、输出结构、最大输出、超时及 providerOptions。连接器负责把统一内容映射到服务实际接受的格式；业务层不直接判断某家服务的字段。

连接配置至少包含：连接 ID、名称、协议、服务地址、密钥引用、允许模型、自定义请求头中的非秘密字段。敏感请求头同样通过凭据引用处理。项目只引用连接 ID 与模型 ID，不携带 Key。

模型配置至少包含：模型 ID、名称、能力声明、声明来源、探测结果、验证时间、上下文与输出上限、价格来源和更新时间。不同服务提供的同名模型分别记录，避免把一个网关的结果推到所有服务。

能力声明与探测结果冲突时显示原因，并以实际可用路径执行。任何模型结果都要经过项目结构校验，不直接作为可发布成品。

## 5. 一次生成怎么运行

1. 读取创作任务卡、选定资料、已确认草稿和锁定字段。
2. 根据阶段组装上下文，带来源定位，预估输入和输出规模；大资料按章节处理。
3. 检查模型是否支持当前任务；缺少图片或结构化能力时明确选择替代方案。
4. 流式展示进度，用户可取消；生成结果先写入候选草稿。
5. 校验结果结构、页面/段落 ID、资料引用和锁定内容，生成差异供用户接受。
6. 保存本轮模型、提示词版本、资料版本、用量、耗时和结果，允许单页或单段重做。

稿件原文和人工修改始终保留。切模型只影响后续生成，不清空项目。相同任务可另出候选版本进行比较。

错误处理采用有限重试：鉴权失败提示检查凭据；限流与短暂网络错误做有限退避；无效结构尝试有限修复，仍失败则保留文本并定位问题。不会无限重跑整套课件。自动重试或切服务不得把资料发送到用户未选定的提供商。

取消会终止可控请求并保留已完成内容；服务端已计费的请求不承诺撤销费用。用量缺失时显示“估算”或“未知”，价格按服务来源与日期计算。用户可设本地任务预算提示与最大输出，不能把本地估算当作服务商账单封顶。

## 6. 推荐模型怎么做

界面提供“均衡、质量优先、成本优先”三个配方入口，详情可展开到具体模型。推荐卡应包含适用任务、能力限制、测试材料、质量表现、耗时、实测用量、验证日期和服务来源。

先用同一套脱敏材料测试，再更新推荐结论。官方模型说明用于确认能力，效果排名由本项目案例产生。未实测的模型显示“候选”，不显示虚构的推荐分数。

### 当前建议优先试的候选

以下为 2026-11-06 核对官方页面后的**试用起点**，尚无本项目 API 实测排名。没有固定价格或永久可用承诺；用户账号、地区和具体服务的实际可用情况在接入时验证。

| 场景 | 首批候选 | 选择依据与试法 |
| --- | --- | --- |
| 复杂结构与逐字稿精修 | Claude Opus 5.5（`claude-opus-5-5`）；Qwen3.8-Max（`qwen3.8-max`） | 先比较原意保留、口语自然、章节逻辑与人工修订时间；不是本项目已证实的效果排名 |
| 日常草稿与批量局部修改 | DeepSeek Flash（`deepseek-flash`）；Qwen3.7-Plus（`qwen3.7-plus`） | 对同一稿件比较可用质量、耗时与实际费用，决定是否作为默认配方 |
| H5 结构与页面实现建议 | Claude Sonnet 5.5（`claude-sonnet-5-5`）；必要时 Opus 档 | 先验证结构化输出和模板遵循，复杂自定义 H5 仅在隔离环境预览 |
| 旧 PPT 截图与图片资料理解 | Qwen3.8-Max；支持图片的 Claude 模型 | 验证中文截图、图表、页内信息与遗漏；生成结果与原页对照 |
| 复杂纯文本规划的另一候选 | DeepSeek V4 Pro（`deepseek-v4-pro`） | 该官方接口当前未标注视觉支持，不用于直接看 PPT 截图 |

官方依据：DeepSeek 当前列出 `deepseek-flash` 与 `deepseek-v4-pro`，并分别说明视觉能力；模型 ID 和别名会变化，应查询而非永久写死。[DeepSeek 模型与能力](https://api-docs.deepseek.com/quick_start/pricing/)、[模型列表接口](https://api-docs.deepseek.com/api/list-models/)

Claude 当前官方目录包含 Opus 5.5、Sonnet 5.5 等，并说明当前系列支持文字与图片输入。上述任务分工是本项目的试验建议。[Claude 模型目录](https://platform.claude.com/docs/en/models/overview)

阿里云百炼当前目录包含 Qwen3.8-Max、Qwen3.7-Plus 等文本和视觉能力入口；不同服务中的模型 ID、限制与参数需分别核对。[百炼模型目录](https://help.aliyun.com/zh/model-studio/models)

GPT、Gemini、Kimi 等保留接入与评测位置；后续按实际账号可用性、协议和测试结果补入。产品接口不限制在本表的厂商。

### 统一测试材料与评分

固定三组匿名材料：一份知识教学材料、一份业务方案材料、一套含图片/图表/备注的旧 PPT。每组先生成三页，再测一份 10–20 页的完整表达。

| 维度 | 建议权重 | 检查内容 |
| --- | ---: | --- |
| 资料忠实与可追溯 | 25% | 数字、事实、引用、原话和讲者经历是否准确 |
| 逐字稿自然与可讲 | 25% | 口语、转场、例子、解释密度与本人风格 |
| 结构与听众适配 | 20% | 目标、顺序、重点、闭环和时长 |
| 页面与节奏 | 20% | 标题、视觉结构、稿页对应与点击时机 |
| 可编辑与稳定输出 | 10% | 输出结构、锁稿保留、局部重做和修复次数 |

这是本项目拟定的权重。先标模型匿名评审，再由讲者试读；费用、等待时间和人工修改时间单独列出，避免质量被低价平均掉。关键事实编造、锁定内容破坏或稿页错位需要先修复，不能靠总分放行。

同一组合至少重复测试并记录波动。保存模型 ID、服务、参数、提示词版本、资料哈希和时间；推荐目录按实际观察更新。第一轮结果不宣传为全行业榜单。

## 7. 密钥和数据

API Key 由桌面主进程管理，优先使用各系统的安全凭据机制；普通工作台、手机、课程 iframe、导出文件和日志均不读取明文密钥。用户可测试、替换和删除连接。

实现时核对锁定 Electron 版本所支持的凭据 API。官方文档当前建议异步 safeStorage API，并说明 Linux 的密钥服务可用性存在差异。检测到缺少可靠系统存储时改为仅本次会话使用，不以普通配置文件保存 Key。[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)

调用云模型前，让用户知道使用哪家服务以及发送哪些资料。备份导出连接配置时去掉秘密，仅保留协议与模型信息，换电脑后重新填写 Key。错误诊断不回显 Authorization、自定义秘密头或完整敏感资料。

## 8. 首轮完成标准

- 用户能够自行接入两家不同服务，手填模型 ID 完成连接测试和三页制作。
- 文字、图片、结构化输出、取消、限流和无效结果分别有可理解的状态。
- 同一项目换模型后保留人工修改，单页重做可对比和撤销。
- 外部智能体生成的结果经过同一结构校验与版本流程，能继续在软件内改稿。
- 推荐目录分清官方能力、项目实测与候选状态，附更新时间和依据。
- 安装包、导出包、手机接口和日志中没有模型密钥。
