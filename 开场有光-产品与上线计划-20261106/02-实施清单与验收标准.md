## 2. 首个技术样机必须回答的问题

### Electron 与现有 Node 内核

- 锁定的 Electron、其内置 Node 与工程当前 Node 24.22.1 要求是否兼容？
- 本地服务放在独立受控进程后，HTTP、SSE、ESM、压缩包处理、关闭与异常重启是否正常？
- 打包后只读资源路径与可写项目路径是否分开？内容包大资源是否需要在归档外保留？
- 现有回环地址检查、私稿凭据与桌面特权边界是否仍有效？
- 三种系统的网络权限、多个网卡、中文字体、外接屏和窗口管理是否有差异？

输出一份技术决定记录，写清采用的进程结构、版本、资源布局和测试结果。若需要独立 Node 运行时，则分别打包平台对应版本并记录维护成本；不把它隐藏为“原代码直接通用”。

### 增量改造

保留原 v0.2.0 发布和历史基线，新建桌面与制作界面模块。先通过适配层复用 `core/state.mjs`、`server`、SDK、Schema 与内容模板，再逐步分离公共模块。原客户端作为回归参照，不一次性搬动所有课程和中文目录。

可采用的目录方向：`apps/desktop` 管系统集成，`apps/studio` 管编辑体验，`apps/site` 管官网，`packages` 管逐步提取的共享结构与适配器。具体文件迁移以 M1 技术结果为准，目录美化不作为完成目标。

## 3. 代表性验收场景

| 场景 | 操作 | 必须观察到的结果 |
| --- | --- | --- |
| 新用户上手 | 干净系统安装，打开匿名课，手机扫码并演示 | 不需要 Node/命令行；连接步骤可理解；私稿对应 |
| 自接模型 | 配置两种实际服务，查询或手填模型，生成同一三页 | 协议差异被处理；模型与资料选择明确；输出可继续改 |
| 原稿保护 | 导入定稿，锁定一段，要求重做页面和转场 | 原文可对照，锁定内容不被覆盖；建议修改需接受后生效 |
| 局部编辑 | 修改第五页，单独重做第六页，撤销一次 | 其他页人工修改和资源不丢，版本可回到修改前 |
| PPTX 迁移 | 导入有备注/无备注、图片、图表和复杂对象的样本 | 页序正确；原备注保留；新增稿标明；不能迁移项可定位 |
| 动画往返 | 连续展开、返回、跳页、黑屏恢复、重新进入页面 | 显示状态与讲稿步骤一致，没有残留或重复展开 |
| 手机失联 | 断网十秒，电脑继续翻页，恢复手机 | 手机离线时禁用控制，恢复后跟上最新状态，旧点击不补发 |
| 锁屏与后台 | 手机锁屏/切应用后返回 | 恢复说明清楚，状态正确，不能恢复时有重新配对入口 |
| 外网断开 | 关闭外网，保留可互通局域网 | 已发布课件、手机稿、控制和计时继续；云模型状态明确 |
| 正式场次 | 演讲中后台修改草稿，再打开排练 | 正式场次固定原发布版本，排练与演讲互不改进度 |
| 长时间运行 | 真实连续演示 60 分钟，包含展开、互动、黑屏与断线 | 无错页、计时异常、持续资源增长或无法恢复；记录起止时间 |
| 版本升级 | 旧版创建/导入内容，升级，再恢复一份备份 | 项目和旧包可用，不沿用旧控制凭据；失败后恢复路径有效 |
| 导出 | 分别导出讲师项目、讲师演讲包和学员材料 | 清单与内容相符；学员材料不含私稿，所有包不含密钥 |
| 异常材料 | 损坏包、越界路径、重复版本、缺资源、超限附件 | 明确拒绝或提示；当前课与已有草稿保持可用 |
| 日志与诊断 | 连接失败、生成失败、导出诊断 | 有可定位错误；不回显 Key、秘密请求头和完整敏感原文 |

现有十项测试继续保留。新增自动化重点覆盖数据迁移、锁稿合并、模型适配归一化、导出隔离和生命周期，避免只验证 UI 文案存在。

## 6. Git 与版本管理

保留私有仓库 `wayofmusic/h5deck-presenter` 的 `main` 和 `v0.2.0` 快照。新工作通过功能分支和可回顾提交推进，不改写已发布历史。

CI 在现有完整性校验基础上增加三系统矩阵。软件代码版本、内容包修订、项目格式版本、模型目录版本分别管理；仅改品牌文案不自动改变内容协议。

公开安装包与匿名素材采用独立发布清单，现有包含私人课程的备份 Release 不用作公开官网下载源。每次发布保存变更记录、依赖锁定、安装包哈希与支持矩阵。

### 对应阶段需要落实的外部条件

| 条件 | 什么时候需要 | 未具备时的处理 |
| --- | --- | --- |
| Windows、Apple Silicon/Intel Mac、目标 Linux 环境 | M1 技术样机与 M5 验收 | 先做 CI 与可下载候选包，对缺少实机证据的平台保留待验证状态 |
| Android 和 iOS 物理手机、可互通网络与投影/第二屏 | M1 初测、M5 现场验证 | 移动视口只作开发辅助，不写成真机通过 |
| 至少两家模型服务可用的测试账号/Key 或受支持本地服务 | M3–M5 | 连接器可先用协议样本开发，实际质量和费用结论等待真实调用 |
| 平台开发者身份、签名证书、macOS 公证条件 | M6 正式分发 | 保留内部构建，公开安装体验和签名状态不作虚构 |
| 公开下载位置、域名与反馈入口 | M6 官网发布 | 先完成本地官网与匿名资源，实际服务选型后接入 |

这些条件在进入相应阶段时核实。开发先完成可交付部分，涉及付费账号、购置或公开服务变更时提供具体方案再落实。
